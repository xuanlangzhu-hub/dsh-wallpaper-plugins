# 第二阶段：原生窗口采集验证

日期：2026-10-03（Asia/Shanghai）。本轮范围在用户后续选择后收束为“先完成采集验证”。

## 结论

**WE 场景独立运行和指定窗口 WGC 采集已实测成功；第二阶段整体仍未完成。**
没有把动态画面接入 DSH，没有验证 DSH 遮挡/最大化状态，没有验证音频反应或输入转发。
当前探针的平均吞吐明显低于稳定 30 fps 的目标。

## 实际执行

- 样本：`3521337568` / Cyberpunk: Edgerunner-Lucy[4K]，`scene` 类型。
- 使用 `openWallpaper -file <project.json> -playInWindow WhaleWallpaperProbe-20261003-01`
  和 1280×720 参数创建独立窗口。现有 WE 主进程继续运行。
- 窗口工具枚举得到 HWND `48498296`，所属 `wallpaper64.exe` PID `12016`。
  这些 ID 只适用于本次记录，后续不得复用。
- 初次观察时测试窗口在聊天窗口后方；主动前置后看到 Lucy、动态粒子与时间组件。
  只能说明本次观察到的启动行为，不能保证所有启动都不抢焦点。
- 通用窗口工具在遮挡时截图混入前方窗口，未用它作为“后台采集成功”的证据。
- 编写独立 .NET 探针，用 WGC `CreateForWindow` 捕获明确的 HWND，GPU surface 回读为
  SoftwareBitmap，再编码 JPEG、记录哈希与状态。保存的画面经人工式图像检查，确认是 Lucy 场景。
- 用窗口工具最小化源窗口，观察采集停止更新；恢复窗口后重新出帧。
- 尝试通过窗口工具显示 DSH 时返回 `Computer Use app approval timed out`。
  没有改用其它方式绕过访问授权。用户随后选择本轮只完成采集验证。

| 帧尺寸 | 1284×767 | 包含窗口边框/标题栏，尚未裁成 1280×720 内容区 |

| 单帧处理耗时 P95 | 425.91 ms | 存在明显波动，尚未定位耗时来源 |
| 结束方式 | stop-file | 正常退出并产生 summary.json |

日志还记录了 `foreground: false` 时仍有新帧和不同哈希；这支持“失焦可采集”，
但没有受控记录遮挡面积，不能把它升级为“完全遮挡可持续渲染”。

本轮没有隔离源渲染、GPU 回读、编码、写盘和工具操作各自的开销；
没有 GPU 利用率或匹配的关闭背景基线，不能据此宣称性能已达标或推断瓶颈。
