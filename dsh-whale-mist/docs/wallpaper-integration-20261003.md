## 受控性能对比

同一 Lucy 场景、同一测试窗口、30 fps 采集上限，默认源窗口内容为 1280×720。
每组 25 秒，frames-only 组 20 秒。除后列的 DSH 遮挡组外，日志确认所有帧源窗口均在前台、未最小化。
表中 fps 为全程输出；耗时中位数/P95 统一排除前 3 秒预热。

| 运行 | 输出 fps | 回读 P50 / P95 (ms) | 结论 |
| --- | --- | --- | --- |
| WinRT 回读 + JPEG + 逐帧写盘 | 5.33 | 100.00 / 543.06 | 复现慢速基线 |
| WinRT 回读 + JPEG，不逐帧写盘 | 5.62 | 86.42 / 481.94 | 去写盘未明显改善 |
| 只做 WinRT 回读 | 5.72 | 85.80 / 557.42 | 去 JPEG 后仍慢 |
| 直接 D3D11 staging 回读 + JPEG | 6.03 | 84.95 / 486.04 | 换回读方式未显著改善 |
| WinRT + JPEG 重复 | 6.39 | 84.36 / 452.35 | 存在组间波动 |
| D3D11 staging 重复 | 5.26 | 95.56 / 524.37 | 不支持“staging 已修复性能”的结论 |
| 640×360 源窗口，WinRT + JPEG | 5.33 | 95.60 / 628.34 | 降低尺寸也没有改善 |
| 只取 GPU 帧，不读取像素 | 21.21 | 不适用 | 取帧循环本身明显更快；不是图片输出性能 |

基线 JPEG 编码 P50 约 7.45 ms，写盘约 3.08 ms。慢点集中在 GPU 回读路径，
并非 JPEG 或磁盘主导；但不能据此认定某个 GPU 驱动/API 是唯一根因。
采集设备日志确认 Intel UHD Graphics、LUID 106750。
一次 WE GPU 引擎采样显示相同 LUID 的 3D 引擎利用率 62%；没有完整 GPU 基线，不作因果归因。

## 遮挡与最大化

本轮通过窗口工具成功显示 DSH。先让 DSH 在源窗口前方，再点击其最大化按钮，
截图确认 DSH 最大化，原生采集的 JPEG 仍是 Lucy 场景，哈希持续变化。

- 最大化请求时的采集记录：约 24.64 秒，528 帧，242 次变化。
- 最大化后的记录：约 48.24 秒，977 帧，668 次变化。
- 整段 120 秒：2161 帧、1852 次变化，平均 18.00 fps。
- 该组回读 P50/P95 降至 16.61/24.00 ms。

当前 WE 的“应用最大化时暂停”设置没有阻止这次独立窗口样本的更新。
这只验证本机、此样本与此次状态，不扩展到其它壁纸/设置组合。
背景状态的性能明显好于源窗口前台状态；这属于运行状态差异，不能冒称来自代码优化。
最小化停帧的先前结论仍成立；真正隐藏窗口尚未测试。

## DSH 接入与文件交接修复

临时包源码在 `qa/wallpaper-preview`，包名 `dsh-whale-wallpaper-probe`，版本 0.0.1。
Host 使用官方 webServer 注册两个固定路径，客户端通过同源请求取图。
只读取本次固定临时目录的 latest.jpg/status.json；不开放任意本地路径，不自建对外端口。
客户端在 #root 后方挂图片层，保留原界面交互；每次请求结束后约 80 ms 再请求。
帧计数表示成功解码次数，不等于不同画面数或精确播放帧率。

首次接入约 2.54 秒后在 File.Move 替换图片时出现 UnauthorizedAccessException。
修复包括：有限重试、冲突时保留旧完整帧并跳过发布，以及捕获顶层异常正常退出。
Windows 文件锁自测先复现失败，再验证锁定时不崩溃/不破坏旧帧，解锁后恢复发布。
旧失败进程与错误对话框也已清理。

修复后重新运行：

- 180.05 秒，3861 帧，2275 次哈希变化，平均采集 **21.44 fps**。
- 回读 P50/P95：9.10/21.50 ms；没有统计到跳过发布。
- 官方 DSH 插件页和聊天页都观察到背景；客户端计数至少增长至 1456 帧。
- 背景在当前遮罩下较暗，文字可读；没有完成输入、选字和所有按钮的完整回归。
- 采集到期后，客户端显示“画面已断开”，背景隐藏并恢复原主题，已截图观察。
- 源停止和卸载恢复已验证；停止按钮/Esc 尚未独立完成全链路验收。
- 本轮桌宠在开始时已不在启用 bundles 中，保持用户现状，没有把共存写成已验证。

当前采集输出与客户端播放不是同一帧率；不能宣称“DSH 已达到 21/30 fps”。
图片写盘与轮询用于验证通路，后续需要内存中的传输方式、限速和窗口生命周期设计。
