## D1 [P1] 停止后开始/重新开始可能没有背景，改参数才恢复

用户在最后一轮报告：点开始后背景没有直接出现，调整透明度等设置才恢复。
独立隔离浏览器使用真实主题客户端复现了同一模式：
首次开始绘制 → 停止 → 再开始，画面层不存在；
修改亮度后画面层重新出现。

原因位置：src/client.js 的 unmountWallpaper、paintWallpaper、reconcile 与 runPreview。
停止会移除 wallpaperLayer；开始/重新开始只调用传输层，没有确保新一轮挂上该层。
画面到达时 paintWallpaper 因层为空而丢弃；设置变化才通过 reconcile 重新 mount。
证据：repeat-preview-repro.json（layerAfterSecondStart=false；
layerAfterParameterChange=true、parameterChangeRestoredPicture=true）。

要求：开始每一轮前，在当前来源/主题仍适用时确保有正确的新画面层与订阅。
停止/失效后再开始、重新开始、切换来源后再返回、恢复默认期间迟到帧都要保持生命周期一致。
旧层和旧订阅不重复；不靠用户调整参数唤醒。

## D2 [P2] 新一轮沿用累计帧数和延迟，显示帧率虚高

位置：src/client.js 的 createWallpaperEngine metrics、start/restart、snapshot。
metrics 和延迟累计量只在控制器创建时初始化；
新一轮只重置 startedAt 与状态里的 rendered=0，底层计数没有归零。

真实第三/第四会话的客户端绘制计数为 2332、3294，
而对应新采集总帧数只有 776、1014；seconds 却从本轮 0 重新开始。
所以状态行可能显示远高于真实采集帧率的数字。
独立复现再次开始后计数从前轮继续增加，见 repeat-preview-repro.json。

要求：在真正取得新一轮启动成功且代号仍有效时，重置全部本轮计数、延迟和来源序号，
并保持旧代号回调无效。恢复同一轮短暂停帧不能错误清掉该轮数据。
补开始 → 停止 → 再开始，以及 restart 的断言；
每轮 UI 数字和提交 Host 的指标都要属于当前轮次，不能只改文字显示。

## D3 [P2] WE 背景选项误标成“背景壁纸”

位置：src/client.js 的设置 row 选项文案。
背景枚举使用 wallpaper，通用 row 直接取 copy[value]，
copy.wallpaper 原本是章节标题“背景壁纸”，因此选项没有显示 Wallpaper Engine。
用户找不到预期入口；点选“背景壁纸”后才出现实验控件。

要求：背景来源 wallpaper 选项使用 copy.wallpaperEngine，
保留章节标题原意。补中英文选项的真实文字断言，
不能只验证 data-wm-value=wallpaper 存在。
