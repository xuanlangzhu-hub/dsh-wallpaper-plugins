# WE 内存流验证：实验插件 0.0.2

日期：2026-10-04（Asia/Shanghai）。本轮完成内存中的传图链路和官方 DSH 短时验收。
正式 Whale Appearance 仍为 0.6.0-rc.1，实验插件在验收后移除。

## 改动与范围

原链路逐帧写 latest.jpg，客户端约每 80 ms 发请求取图。新链路为：

`WE 独立窗口 → WGC/JPEG → 原生 stdout 管道 → DSH webServer 流 → 浏览器解码并绘制 canvas`

- 帧号、采集时间估计值和尺寸放在固定 24 字节 WHL1 头部，后接 JPEG。
- Host 和浏览器都只保留最新待处理帧；慢客户端在可写后获取最新帧，不堆积旧画面。
- 浏览器持续读取同一个响应流，用 createImageBitmap 解码，绘制后释放位图。
- 画面不写盘；只保留帧元数据、状态和最终统计。
- 使用既有认证 webServer 路由，不额外监听网络端口，不从 HTTP 接受路径或启动命令。
- 本地临时配置指定经枚举得到的窗口 HWND，原生程序继续验证 WE 进程和测试窗口名前缀。
- 结束实验按钮关闭客户端流，并请求 Host 关闭采集 stdin；父进程断开和卸载也会回收子进程。

仍是 JPEG 回读方案，没有引入 GPU 视频编码；真正隐藏源窗口、音频、输入转发和正式设置集成仍未完成。

`WhaleWallpaperProbe-20261004-memory-01`。采集内容尺寸为 1284×767（含窗口边框），
请求上限 30 fps。记录中源窗口始终未最小化、未处于前台，DSH 在其前方。

| 浏览器收到 / 实际绘制帧 | 2206 / 2200 |
| 客户端统计时长 | 103.33 秒，平均约 21.29 fps |

DSH 截图显示 Lucy 背景以及约 20–22 fps 的实际绘制计数；点击结束实验后显示“实验已停止”，
背景恢复、原生进程退出。卸载后再次检查，实验控件不再存在。

帧数包含重复内容，不能等同于独立动画变化次数。延迟由 WGC 单调时间戳转换到本机 UTC 再与
浏览器绘制时间比较，是软件估计，不是硬件测得的端到端延迟。
旧轮询实验没有同样的显示时间戳，本次不声称严格的性能提升倍数。
30 fps 目标尚未达到，也未进行长时内存/GPU 压力验收。
