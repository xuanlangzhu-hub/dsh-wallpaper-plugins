## 已经排除的解释

- 「边界滞后」：同步更新后几何滞后归零，固定区域像素**依旧**出现 → 不成立。
- 「截图返回旧帧」：同一位置连拍两张、逐帧比较投递延迟与配对误差，泄漏帧与干净帧无可区分差异 → 证据不足。
- 「参考框换成滚动口顶边」：实测该边沿也随滚动移动（`scrollTopEdge` 恒 92，但 `viewTop` 从 92 → −2386），
  滞后样本从 0 涨到 367 → 明确失败，已回退。

## 建议接手方向（未验证，只是线索）

1. 先确认 `clip-path: inset(...)` 在滚动进行中的合成器行为：自定义属性每帧变化是否会导致
   某些帧落回未裁剪路径。若属实，修法是让裁剪值**不随滚动变化**（即真正的固定基准），
   而不是继续追赶内容。
2. 固定基准的候选：卡片顶在屏幕上的位置（`cardRect.top`）本身是恒定的 552；
   需要找到它在 DOM 里"相对哪个盒子"是常量（我的口沿实验说明不是滚动口边沿）。
3. 若下一种有界方案仍失败，请保留失败脚本与差异，不要用"没测到"当"没有"。
