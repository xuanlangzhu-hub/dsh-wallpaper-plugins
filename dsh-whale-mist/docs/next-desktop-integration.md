## 安装与启动方式

1. 使用受管模式的本地配置 `%TEMP%\whale-wallpaper-probe-live.json`，配置 helper/output/file/seconds/fps，
   **不填写历史 hwnd**。location 可省略让 Host 自动生成，也可用每轮新的随机唯一名。
2. 每次重新启用都使用新的 output 目录（放在 `.tmp/<本轮目录>/<轮次>`）和唯一窗口名。
   原生程序拒绝覆盖已有 frames.jsonl/summary.json，这是保护证据的正常行为。
3. 配置样例沿用 Lucy：
   `E:\SteamLibrary\steamapps\workshop\content\431960\3521337568\project.json`。
   WE 路径上次为 `E:\SteamLibrary\steamapps\common\wallpaper_engine`，现场重新核对。
4. 一次运行建议 seconds=180、fps=30；在完成观察后主动停止，不需要把时限跑满。
5. 通过官方插件机制安装/启用 0.0.6。已有前端停止按钮只有“停止”，没有“再次开始”；
   下一轮通过**停用 → 更新本地配置 → 重新启用**建立新实例，不能重复点击已停用按钮冒充新一轮。
   必要的宿主冷启动也要使用正常退出/启动流程。

## 一次会话内完成以下场景

默认按下面三轮覆盖连续启停和三种退出方式，总观察时间控制在几分钟。

| 轮次 | 操作 | 必须确认 |
| --- | --- | --- |
| 1 | 启用 → 观察 30–60 秒 → 点“停止” → 停用插件 | DSH 内实际动态图像可见；停止后背景恢复，源窗口和采集进程消失；停用后实验控件也消失 |
| 2 | 新配置、新 output → 再启用 → 观察 20–30 秒 → 在官方插件页停用 | 当前是新轮次；停用直接触发清理，不能只靠运行时限自动退出 |
| 3 | 新配置、新 output → 再启用 → 观察 20–30 秒 → 正常退出 DSH | 退出后本轮源窗口、采集 helper 消失，原 WE 渲染进程与原桌面壁纸保留 |

第一轮观察期间检查一次 DSH 缩放/最大化和一次最小化恢复。只验证恢复后动态显示正常；
没有实际播放时间或资源数据时，不宣称后台暂停节电已验收。

再补一个短故障场景（若已有有效同版本证据则可引用，避免重跑）：

- 启用后只关闭本轮唯一 WE 源窗口，确认 DSH 在约 5 秒内隐藏失效画面并恢复普通主题，
  采集 helper 结束且没有无限重启。可经已验证的原生关闭接口执行，不终止 wallpaper64 主进程。
- 父 Host 异常退出已由原生 owned-location 自动测试覆盖。本轮引用该证据即可，
  不强杀日常 DSH 做故障注入，也不重做已通过的模拟时序。

## 验收口径

- 每轮实际绘制计数持续增长；native 记录 captureSource=window、内容哈希变化。
  截图/现场观察确认确有壁纸动画，而不是仅有计数器、静止首帧或错误窗口内容。
- 源窗口在屏幕外，不盖住 DSH、不抢焦点。任务栏/Alt-Tab 入口仍可能存在，是已知方案限制。
- 聊天文字、输入卡片和按钮能正常使用。无需发送模型请求，只做必要的非提交交互。
- 写明采集帧率与客户端实际绘制帧率；延迟是软件估计。本轮不要求实现稳定 30 fps。
- 停止/停用/正常退出后，身份明确的本轮资源应在 10 秒内清理。
  关闭结果必须是 closed=true；超时或歧义应记录为失败，不能只因进程返回 0 就判定成功。
- 严格按唯一窗口名和本轮 PID/身份核对；原壁纸和无关窗口应保留。
- 首次遇到可复现的阻塞失败时，记录错误和现场，修该点并复测受影响场景；
  不无限重复成功场景，也不扩展到去任务栏入口、音频、鼠标交互或屏幕锚定效果。

## 结束后的恢复

- 正常退出测试结束后，先在 DSH 关闭状态下移除实验包或恢复原启用状态，再恢复原配置，
  避免用旧 output/旧配置重新启动实验。若本轮开始已安装实验包，按开始时实际状态恢复。
- 归档本轮 TEMP 配置；只移除本轮创建的临时入口。测试素材和日志保留在 `.tmp`，原始资产保持原样。
- Profile 恢复时只撤销本轮修改，不覆盖用户这期间自己的修改。
- 本轮开始时 DSH 若已打开，恢复打开状态和原会话；用户开始操作窗口时保留当前窗口。
  不关闭其它应用或原 WE 服务。
- 保留已安装主题包和所有引用中的 tgz；不修改官方安装资源、不恢复旧 Tauri/WSL 维护，不提交/推送。
