# 下一轮：由用户选择哪些区域遮住壁纸

日期：2026-10-07。这是新增需求计划，**尚未实现**。基线为 rc.17（实现 `3d416f0`，短实机记录 `da5956c`），日常使用 rc.1。先完成这一项的小范围客户端设置，再安排启动闪窗/GPU 增量对照。

## 用户要的效果

左侧项目/会话栏保留主题底色也好看，但用户想自己决定哪些区域遮住壁纸。现有 `surface` 不是区域选择；`sidebar=balanced/deep` 调底色深浅，也不是是否透出壁纸。rc.17 的消息裁剪只作用于消息兄弟层，没有裁剪侧栏。截图作为需求参考，不作为 rc.17 播放态侧栏不透明的测量证据。

首版在「鲸系外观」的背景调节附近加入 **区域底色**，两个独立复选框：

- 左侧项目／会话栏使用不透明底色。
- 聊天区使用不透明底色。

提示：勾选的区域使用对应主题实色；未勾选的区域沿用现有底色与界面不透明度。四种组合都可选，切换即时生效、保存后重开保留。图片、视频和 WE 共享；没有背景时保留偏好但不改变日常主题。

输入卡片、菜单/弹窗保持可读，Windows 顶部继续不透明以遮住源窗口白条。首版不提供其透明开关，也不恢复输入区宽黑渐变。未来确有需求时再扩更多区域。

## 实现边界

1. 先核对 status 和最新验收，不与别的 AI 同时改。只改 `src/client.js` 的外观配置、设置 UI 和必要 QA；不改 Host、原生 helper、播放/自动播放语义。
2. 建议新增 `opaqueSidebar`、`opaqueChat` 两个严格 boolean 设置，默认 false。使用既有 v1 存储键，补 `isValidSetting`、`normalizeSettings`、默认/恢复默认；旧配置缺字段、无效字符串或数字都回到 false，**默认视觉必须与 rc.17 相同**。不要把“未勾选”改成强制完全透明，也不要偷偷给聊天区增加原本没有的全局 alpha 填充。
3. `projectSettings` 投影独立属性；`clearProjection` / 卸载清理属性。复选框接公开 `controller.set(key,value)`，补中英文，遵循普通小方框尺寸和窄窗口布局。
4. 仅当实际背景激活时，在侧栏和聊天列**局部容器**绘制对应主题实色。侧栏用现有 sidebar 色（含深侧栏/各配色），聊天列用 base 色。不得通过全局 `--dsw-specific-sidebar-fill` 或 `--dsw-alias-bg-base` 把 frame、输入外围、菜单或其它区域一起改黑。
5. 未勾选回退到 rc.17 的已有规则；主题切换、背景停止/来源为无、高对比度/减少透明度偏好下正确恢复。输入卡片、顶部和消息裁剪继续保持原逻辑。
6. 两区都选实色时，聊天外围不显示壁纸是用户明确选择的结果；两区都未选时，仍必须通过 rc.17 的外围可见/消息不透字检查。切换设置不停止或新建 WE 轮次，不越过手动停止后的自动播放限制。

## 必须交付的验证

- 旧配置与不合法布尔值、两开关的 UI 回调/持久化/重置/卸载清理；窄窗口下复选框仍为小方框，标签可读。
- 同一幅可辨识背景、同一轮播放，四种组合分别验证侧栏/聊天列像素；勾选的一列只呈主题底色，另一列按原规则显示背景。主 frame/顶部/卡片不能被错误连带改变。
- 消息仍在输入区消失，多行输入与菜单正常；两个开关默认 false 时继续跑现有消息像素检查。故意把 frame 涂实色、把两开关联动或去掉裁剪，应分别被断言拒绝。
- 图片/视频/WE 共用状态、切无/停用恢复，四配色和浅色的对应底色轻量检查。不要求为了颜色设置重复 35 分钟或开展真实 WE/GPU 实验。
- 运行适用的 check、外观/壁纸、布局/像素及仓库必要检查。新候选 rc.18（先查占用），同步 README 后打包、核对内容与指纹，保留所有旧包。
