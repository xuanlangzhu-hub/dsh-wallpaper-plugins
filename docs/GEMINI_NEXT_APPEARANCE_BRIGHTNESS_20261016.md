## 要解决的问题

用户此前反馈“亮度拉满仍不够亮”。当前`src/client.js`中的`brightness`限制为20–100，投影为`--wm-bg-brightness = value / 100`，背景媒体使用CSS `brightness()`；100%只是这层滤镜不调暗，后面仍有主题色遮罩和界面底色。中文提示“只调暗壁纸本身”与新目标也需一起调整。

遮罩是主题底色的透明叠加；深色主题通常压暗，浅色主题也可能提白/染色，不能一概解释成黑色遮光层。需要让用户知道亮度与遮罩各自控制什么，避免把100%误解成最终画面必定等于原壁纸。

## 本次实现

1. 将亮度范围改为**20–200，步长1**，沿用现有百分比和CSS倍率映射：20→0.2、100→1、150→1.5、200→2。100%以下含100%的旧数值保持原含义；默认亮度仍70，不自动抬高用户设置、不引入新的曝光算法。
2. 保留现有`brightness`字段、`dsh-whale-mist.appearance.v1`存储键和归一化流程。正常旧值20–100原样读取、保存；新值能保存并重载。有限越界值按新边界夹取，非法类型/非有限值沿用当前读取默认值、controller.set拒绝非法输入的区别，不重置其它字段。
3. 滑块实际min/max、显示值、校验与保存使用相同范围；按现有布局显示百分比。修改后即时更新背景滤镜，不重建媒体、不重新解码当前图片、不重启视频或WE播放。
4. 同步中文和英文说明。建议意思为：“100%保留原亮度，可继续提亮；最终效果还受遮罩和界面底色影响”。遮罩说明为：“叠加主题底色；数值越大，主题底色覆盖越强，0%关闭这层遮罩”。保持简短，不把渲染实现细节塞进设置流程。
5. `mask`范围0–90/默认45、blur、surface及其它默认值不变。降低遮罩不连带修改亮度、界面不透明度或主题；停止/移除背景的既有恢复行为保持。

200%是这次实现上限，不承诺高亮处无过曝或把纯黑细节恢复出来。不新增对比度/饱和度/自动取色，不扩成滤镜面板；不需要额外弹窗或迁移向导。
