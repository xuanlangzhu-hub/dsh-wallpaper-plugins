## S1 [P2] 总截止时间只约束调度，没有约束进行中的查询和启动

位置：src/client.js 的自动播放 effect：deadline、eligible、scheduleRetry 与 attempt。
run / scheduleRetry 检查 Date.now()，但 attempt 进入及 await loadHostStatus 后没有检查 deadline。
每次查询固定可等待 4000ms，未按剩余总窗口收敛；因此窗口内开始的查询可能在窗口外触发 start。

独立页面使用生产默认读取时限与会响应 AbortSignal 的模拟 Host：

- 查询时间约为 15 / 324 / 5836 / 11359ms。
- 12416ms 时仍有 1 个查询等待，启动数 0。
- 这时放行最后查询；13021ms 时启动数变 1、状态 playing。
- 声明的总截止时间为 12000ms，期望总窗口结束后启动数仍为 0。

这不是原来的无限挂起：单次查询超时已经实现；剩下是总期限与在途查询没有联动。

最小修正：

1. 发查询前确认尚未超过总截止时间。
2. 本次读取超时取“读取默认上限”和“剩余总窗口”中较小者，到期取消读取。
3. await 返回后再次确认仍在总窗口内，再决定是否允许 start。
4. 到期清掉重试计时器，保留已有的手动停止 / 模式与来源取消代号。

补一个“期限前发查询、期限后返回 available=true”的回归，确认不会 start；
同时保留期限内恢复后恰好一次启动的用例。不要把总窗口改大来回避该分支。
