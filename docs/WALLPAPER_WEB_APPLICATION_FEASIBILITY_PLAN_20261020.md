# 剩余壁纸类型可行性：先 web，再 application

2026-10-20，用户确认：“清理推送，然后还是先把壁纸可行做完再做设置”。本轮维护完成后继续此排期，作者公开参数后排。当前日常为[rc.40](RC40_DAILY_TRIAL_20261020.md)，不会因为可行性调查直接升级安装或启用未知壁纸。

| 类型 | 当前已有结果 | 剩余范围 |
| --- | --- | --- |
| scene | 已有受限目录登记、手动选择、源窗口/采集链；Lucy回归通过 | 不承诺每张scene的脚本、音频、交互均正确；三体演算变速专项继续暂缓 |
| 本地MP4 video | [rc.40短验](RC40_VIDEO_ASCII_BRIDGE_SHORT_TEST_20261020.md)中批准的Everyone视频连续播放、操作及停止通过；受控ASCII副本已接入 | 不扩大为所有容器/编码/音频均通过；维持当前格式和路径门禁 |
| web | 当前catalog、Host与主从播放执行器未开放此类型 | 先只读确认本机声明形态、入口和依赖，再判断独立源能否正确打开、限定归属并清理 |
| application | 当前未开放，未验证可安全接入 | 在web得到结论后调查入口、进程/窗口归属、权限和退出边界；未经单独批准不运行壁纸附带可执行文件 |

“可行性做完”应分别得出有证据的结论：可接入及适用边界，或暂不支持及具体阻碍。不是把列表中的所有项目都标为可用，也不是承诺任意网页/程序都可运行。

## web 第一小步：只读调查与离线任务

1. 查现有受限目录中的类型声明结构；默认Everyone，不读未勾选分级的预览图，不将壁纸正文、个人资源或附带程序加入仓库。
2. 对照当前catalog/library、Host/session、helper参数、主从执行器契约，列出仅允许scene/MP4的实际门禁与需要调整的位置。不要仅修改UI类型判断。
3. 核实官方独立窗口启动接口对web项目的输入要求、运行依赖和限制；区分文档支持、静态声明、真实可见播放三种证据。
4. 设计最小受限样例及有界验证方案：唯一location、启动/失败/超时/停止/迟到结果、源窗口和进程归属、原WE保持。先离线替身负例，真实开窗另取当时方便确认。
5. 输出调查报告与最小实现任务。若发现需独立浏览器或其它渲染路线，先说明行为/资源/归属差异，不将任意URL直接塞入DSH页面。

## application 后续门槛

先报告声明能否可靠定位入口，是否可限定到独立实例，窗口/子进程能否完整归属、正常关闭及保留原桌面WE。缺少这些证明时保持禁用，说明阻碍和可选后续；不为了凑齐类型直接运行未知EXE、请求管理员权限或采用全局杀进程。

## 保持的边界

日常DSH/Profile/原WE不动，工作区manifest/生产assets仍rc.30。年龄分级、选择与播放分离、停止清理锁、Lucy-only自动播放保持；音频/输入转发与作者参数分别验收。所有脚本须有总期限、阶段期限、实际子进程退出确认和独立证据目录，不恢复定时任务，不重开A/三体/GPU专项。
