# 原生侧栏：四字段手动外观预设

2026-10-23，接续[无背景启用WE](WALLPAPER_NATIVE_ENABLE_SOURCE_20261023.md)，按[剩余入口盘点中的预设方案](WALLPAPER_NATIVE_REMAINING_ENTRIES_20261023.md)实施。本轮仅开发源码及离线验证，不制作候选或操作日常应用。

## 结果

“壁纸画面”中，背景模糊之后新增默认收起的**本壁纸外观预设**。折叠时不挂载预设操作按钮，原首屏按钮数量保持；有背景但目标／状态不安全时显示简短不可用状态，没有预设能力或不是WE背景时不放占位入口。

- 没有预设：展开后主操作为“保存当前四项”。
- 已有预设：主操作为“恢复已存外观”；相同值时禁用重复恢复。保存／覆盖及删除收进有名称的“更多”折叠入口，不把旧三按钮并排搬入首屏。
- 覆盖不同值、删除均就近确认／取消；确认覆盖时显示将保存的四项，删除不改变当前外观。目标、偏好、源代次、预设内容或安全上下文变化后撤销旧确认。
- 成功以实际状态与1.2秒完成标记反馈，隐藏／关闭／卸载清理计时；不追加常驻成功段落，不自动重试。错误就近短提示，不展示原始命令或私有异常内容。

沿用原 `controller.presets`、v1存储、每个壁纸ID一份的语义；**仍只含亮度、遮罩、背景模糊、界面不透明度**。不保存主题、强调色、聊天底色、自动播放或作者参数，不新增命名库、导入导出、自动保存／自动应用。选择壁纸不自动恢复预设，普通调节不自动覆盖已存记录。

原生入口继续核对原resolveTarget结果、所选／活动一致、目录与分级、背景来源、实际主题、会话、合法代次、命令门禁与清理状态。活动时仅稳定playing且同一目标允许操作，连接／等待／异常／未知关闭期间拒绝。动作必须携带当时的有效目标ID；不使用undefined退回当前任意目标。

另绑定视图可见与展开许可，折叠、隐藏、abort、旧页占用、卸载后不能用旧事件或确认执行。浮动副本共享同一controller和一个预设订阅；一个副本不能确认另一个副本的删除。服务替换先释放旧订阅，再建立新订阅。

## 原恢复流程的真实负例与最小修补

隔离SDK `preset-notify-before-sdk` 通过真实controller保存80／40／0／70，然后将当前值改为60／60／4／90，并只让真实backdrop更新抛错。恢复后记录：

| 观测 | 亮度 |
| --- | --- |
| `controller.read()`的真实内部值 | 80 |
| 本地存储 | 80 |
| `getSettingsSnapshot()`公开快照 | 60 |
| 原生滑块 | 60 |

页面异常0，测试失败在预期的60≠80；自有浏览器及服务正常清理。原输入和报告保留。存储仍为旧值、仅React延迟两种解释均被上述读数排除；原因是原 `presets.apply` 在改值后先project／update，抛错会跳过通知。

本轮只将原apply的project／update包在 `try/finally` 中，实际值改变时保证发布快照；不吞投影异常，不重试，不更改存储／播放／作者流程。新入口捕获异常后先刷新真实上下文，再保留局部“预设操作未确认，请核对当前状态”，避免上下文失效时把错误一并清掉。

同一负例修补后通过；最终14项SDK也保留此故障注入，真实值、公开快照、滑块、存储均为95，同时继续呈现未确认错误，不显示成功标记。它证明异常后的状态发布修复，不是证明投影失败也已成功显示壁纸。

## 持久化的既有边界

预设save／remove检查原 `persistPresets` 的失败结果。SDK分别对真实浏览器预设存储注入QuotaExceededError，均保留原记录，不假称已保存／删除；恢复后只在下一次明确动作重试。

原apply使用的 `persistSettings` 仍会吞存储异常，本轮未扩大修补该通用函数。对此也做了真实浏览器故障注入：当前值与滑块成功恢复到95，存储仍是55。界面只反馈**当前外观已恢复**，不反馈“已保存”或承诺重启后保持。实际偏好回声不能代替持久化证明；这项限制保留在报告中，不能被ok结果掩盖。
