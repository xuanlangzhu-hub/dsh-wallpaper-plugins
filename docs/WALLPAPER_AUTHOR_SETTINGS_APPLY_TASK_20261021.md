# 作者设置 P1B：限定当前壁纸的参数下发

2026-10-21。接[P1A双端草稿交付](WALLPAPER_AUTHOR_SETTINGS_P1_DRAFT_DELIVERY_20261021.md)，继续源码离线。日常DSH0.2.1-rc.2/rc.42/Git Bash0.1.1保持；不整包开发树、不安装、不操作DSH/WE或调用真实参数命令。

## 要完成的唯一功能

把经Host认证及修订校验的已保存修改增量发送给当前同ID壁纸。由一个Host adapter持有任务，主侧栏和独立窗只提交ID/fingerprint/revision，不接收前端JSON、可执行路径、location、PID或任意命令。B的草稿不能应用到正在播放的A。

1. 先确认实际WE `applyProperties`协议及Windows传参边界。沿用可信WE可执行路径和同轮named location，参数数组始终带`-location`；RAW分隔符/JSON和值约束保持。没有当前活动ID、可验证PID/启动时间、location或停止代次就拒绝；不退化为全桌面更新。
2. 命令前后重验真实窗口及会话身份、主注册/lease、选择与分级、schema/草稿修订、stop/unload代次。异常、超时、未知退出或迟到结果不能报成功或解锁第二个未确认任务。停止和卸载主动取消；只收束本轮自有命令进程，绝不杀原WE或改其全局设置。
3. 设置总期限、阶段期限和有界输出。合并/节流连续编辑，显式点击应用，不能每次渲染下发。已有表单4秒deadline应与真实adapter期限协调，避免HTTP返回后命令仍无限后台运行。保存草稿与应用是不同动作，默认值只能在显式确认恢复默认时全部下发。
4. 单独验证ASCII、中文/Unicode、引号、反斜线和RAW边界。中文草稿通过HTTP不证明WE CLI支持；不改系统代码页，也不把MP4文件副本桥照搬到参数或网页配置。
5. UI仅在adapter离线链通过后开放按钮；返回“已发送”与“作者代码响应”分开，不能声称读取了WE当前值。失败保留草稿及可解释状态，双端冲突需刷新，不自动覆盖。
