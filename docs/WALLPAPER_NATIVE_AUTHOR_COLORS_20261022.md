## 已实现

原生最右侧作者区增加颜色行：作者标签、可展开色块、六位`#RRGGBB`输入；展开后显示R/G/B三个通道。沿用侧栏字体、主题、强调色和完成/忙碌标记，不增加保存/应用按钮组，不弹出系统取色窗口。

| 操作 | 提交行为 |
| --- | --- |
| 展开、收起，或聚焦后不修改 | 不发送；保留原始RGB精度 |
| RGB拖动或连续按键 | 只预览，松手或按键结束后提交最终值 |
| 输入完整六位色值 | Enter或正常移开焦点后提交一次；之后继续输入可开始新调整 |
| 格式不完整/错误 | 不写草稿、不发命令；显示短错误，失焦后丢弃本次输入 |
| Esc、取消、关闭RGB调节区 | 丢弃尚未完成的通道调整，不发送回退命令 |
| 收起侧栏、切目标/代次或卸载 | 作废本地票据，迟到事件不能提交 |
| 等待上一条命令期间完成多次修改 | 保留各字段最新值，仍串行发送 |

颜色初始值仍是作者默认值或插件记录，**没有读回WE当前值**。HEX/8位通道显示是近似表示；只打开或聚焦不会将原始`0.5 0.123456789 1`舍入下发。调节一个通道只替换该分量，其它分量保留原精度。明确修改HEX时才转换为8位RGB对应的归一化数值。

本步使用内联调色，未承诺系统取色器、色轮、透明度通道、HDR、gamma/sRGB转换或所有辅助技术输入。实现沿用既有作者颜色协议的RGB分量解释，未改色彩空间。

## 安全与宿主焦点处理

新增UI转换函数只负责RGB显示和六位HEX解析；所有可编辑字段和值继续经过已有`validateAuthorValue`。没有改Host、协议、原执行器或鉴权。支持的颜色描述符和规范记录才可进入原生控件，不支持/条件字段仍由原schema判定。旧调用者未传验证函数时仍仅展示布尔字段。

本地预览继续使用前轮的独立编辑Map，每字段单一所有者、票据绑定epoch/context/可见视图。增加只读`editCurrent(ticket)`供保留的React组件核验本地票据是否已失效。读取/清除4秒、写入总12秒/最多4批、旧物理请求未结束不解锁、revision/fingerprint精确核对、未知结果和明确恢复路径均保留。

实际SDK暴露了一个事件顺序问题：宿主收起侧栏时先转移焦点，输入框可能在React收到`tab.visible=false`前失焦。若直接把所有失焦都当作完成，预览会进入提交队列，随后被隐藏取消，留下错误态。只检查React可见性或旧票据不足以防止该顺序。

现在完成提交前，使用SDK既有只读`sidebarRight.focusedTarget(inputNode)`核对该输入当前仍属于可见页面；不可确认时取消，不依赖上一帧可见性。此保护同时用于普通滑块和RGB/HEX控件。没有拦截/修改宿主命令或焦点，也没有全局延迟提交或轮询。

浮动面板不能简单以主侧栏`isExpanded=false`判不可用，因此通过实际SDK验证：主侧栏收起、浮动作者页仍可见时，HEX正常失焦提交，两个真实occurrence同步值且ID不同；关闭浮动页后只剩一个控件。宿主缺少该即时目标查询能力时完成操作保守取消，不伪造成功。
