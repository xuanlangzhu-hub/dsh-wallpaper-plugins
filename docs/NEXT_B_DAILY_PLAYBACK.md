## 3. 日常播放：完整接通时限与停止语义

当前限制同时存在于：

- `src/wallpaper/scenes.js`：Host 预览默认 180 秒、最多 300 秒。
- `src/wallpaper/session.js`：请求重新校验并把秒数传给采集子进程。
- `qa/wallpaper-probe/Program.cs`：原生参数只接受 1..1800 秒，循环按 duration 结束。
- `src/client.js`：开始 / 重新开始的请求、设置持久化、状态行与倒计时。

增加明确的预览 / 日常模式，沿用预览为迁移默认值。缺少模式的旧请求仍按预览处理；
新字段使用受约束的枚举，非法模式拒绝。前端仍只能提交场景 id 与受支持的模式 / 预览秒数，
不能提交命令、文件路径、窗口句柄、任意坐标或原生参数。

日常模式需有真实的无定时结束语义；不能只提高 UI 秒数，不能把 1800 改成某个很大的数字，
也不能靠定时重开源窗口续播。继续依赖停止命令、父管道断开、源窗口消失、故障和宿主退出结束会话。
原生日常模式必须与本轮唯一资源归属及父进程停止通道绑定；有限时长的 QA / 预览行为保留。

日常模式不显示虚假的预览倒计时，显示正在播放、已运行时间、实际本轮帧数等状态。
开始、停止、再次开始和重新开始使用真实设置控件回调，只调用公开 controller 接口。
每轮计数归零、缺失画面层自建、旧代号回调失效与未确认清理的重试逻辑必须保留。

运行中改模式需要明确当前会话与下一次启动的区别；重启采用新模式时，先确认旧轮清理完成再创建新轮。
自然结束、断流和子进程退出后恢复普通主题，给出原因，不自动无限重建壁纸窗口。
现有 native 全局 Esc 轮询属于实验停止行为：日常模式不能因用户在其它应用按 Esc 而意外停播；
日常的显式停止入口与父进程结束清理必须可用，实机操作期间用户要求停止则立即停止测试。

## 4. 自动播放与窗口恢复

- 增加持久化的自动播放选项，旧设置缺失时为 false；含义是随 DSH 启动，不创建 Windows 开机任务。
- 勾选只保存下一次启动的选择，本轮仍由播放按钮开始；取消自动播放不应意外终止当前手动会话。
- 自动开始仅在日常模式、WE 来源、适用主题和 Host 就绪时触发，一次启动只创建一轮。
  服务稍晚就绪可有有界等待，不通过反复建窗实现重试。
- 同次 DSH 运行中，用户手动停止后保持停止；改亮度、主题重同步或组件重挂不能悄悄重新开始。
  用户再次按播放或下一次完整启动 DSH 才重新按意图执行。
- 切换为无 / 图片 / 视频、恢复默认、插件停用或退出，均取消迟到的启动请求并清理自己的资源。
- 最小化 / 恢复后可继续显示新帧，单纯失焦不能导致反复重建源窗口。
  本轮至少避免隐藏页面持续解码 / 绘制；若原生仍持续渲染、采集，明确记录后台开销。
  更完整的游戏模式、省电和休眠策略留待实测后另定，不调用 WE 的全局 pause / stop / mute。
- 短暂停帧与恢复沿用有界处理；若主动暂停，状态与 watchdog 必须一致，避免把正常暂停当故障。

## 5. 长时间运行的资源与日志

画面仍使用最新帧与背压约束，不因 UI 隐藏或读取变慢而积累无界队列、Bitmap 或未完成 Promise。
停止 / 重启后释放旧 reader、Bitmap、定时器和监听器；被隐藏后恢复时不显示旧轮画面。

原生当前会逐帧写 frames.jsonl。日常模式需使用采样、聚合或滚动等有界日志策略，
明确单会话体积上限，保留最终统计、错误和资源关闭结果；不能随运行时间无限增长。
沿用受控目录和轮次保留约束，只管理自己创建的日志，不用通配符清理别人的证据。
实际绘制帧与原生帧、变化帧、平均延迟分别记录，不能把重复帧或累计指标当成本轮性能提升。

## 6. 启动闪窗：一次小验证，结果不阻塞日常模式

当前顺序是创建可见窗口 → 建立窗口采集 → 收到 window 来源状态 → 再调用 helper 移出屏幕。
`SourceWindowHelper.OpenWallpaper` 只传 playInWindow、width、height，尚未使用初始位置。
[WE 官方控制接口](https://help.wallpaperengine.io/en/functionality/cli.html) 提供 x / y 参数。

在原生 / Host 侧验证固定的屏幕外初始位置，例如已有方案的 (-32000,-32000)，保持正常窗口可见属性与唯一名字。
位置由可信代码决定，保持 WinSta0\\Default 对齐和身份校验；不先 SW_HIDE、最小化或改 TOOLWINDOW 样式。

先准备参数检查与测试，不自动弹窗做实验。用户当前方便后，由外部助手配合：

未完成真实验证的初始屏幕外路径默认不启用，保留供外部验收的显式实验入口；日常候选仍可沿用已验证的收起流程。

1. 用 Lucy 做一次 30–60 秒最小验证，确认从屏幕外开始仍可建立 WGC、持续得到 window 来源变化帧。
2. 记录建窗调用、首次发现窗口及位置、采集建立、首帧、DSH 首次绘制等时间点，分清延迟来源。
3. 用户观察是否出现可见闪窗或抢焦点；停止后验证本轮窗口、采集消失，原 WE 保持正常。

初始位置可能被 WE 调整，或导致初始化失败；如不可行，记录证据并保留已验证的先采集后移出方案。
可以做一次有界回退，但不能循环弹窗重试；不为失败扩大成完整隐藏研究。
只记录实际改善与仍存在的入口，不凭命令返回 0 或最终位置在屏幕外宣布“全程零闪窗”。

## 7. 检查与实机验收

先完成无需真实 WE 窗口的检查，再交候选版给 Codex 审查：

```powershell
Set-Location F:\dsh-wallpaper-plugins\dsh-whale-mist
npm run check
npm run test:wallpaper-host
npm run test:appearance
npm run test:appearance-wallpaper
```

SDK 检查在修正本检出路径与副作用隔离后运行；原生有改动时构建并核对 packaged helper。
围绕新行为增加必要断言：日常超过旧 300 / 1800 秒边界仍运行，预览正常到期；
未知模式拒绝；父断开仍清理；真实按钮的模式传递；自动播放默认关闭 / 只启动一次 / 手动停止后不自启；
来源切换和卸载期间迟到请求失效；日志有界。加速时钟检查不能代替真实长时观察。

实机由用户点击、外部 Codex 核验。DS 不自行安装日常插件、不退出正在承载自己的 DSH，也不抢鼠标。
需要窗口验证时先交准备材料，等用户方便后配合一次有记录的验收：

| 场景 | 通过条件 |
| --- | --- |
| 预览回归 | 仍有限时长，真实停止按钮正常 |
| 日常持续播放 | 同一轮连续至少 35 分钟，跨过旧 5 / 30 分钟上限，没有定时重开窗口；画面实际变化 |
| 长时数据 | 记录暖机后、5 / 15 / 30 / 35 分钟的 CPU、内存、GPU（可取得时）、帧与延迟、日志体积；没有无界增长或无法恢复的冻结 |
| 最小化与恢复 | 有新画面恢复，帧计数仍属当前轮，不重复建窗；输入、选字与缩放正常 |
| 手动停止 / 再开始 / 重新开始 | 每轮正确出图与归零，closed=true；旧 Bitmap、reader、计时器与源窗口没有残留 |
| 自动播放关闭 / 开启 | 关闭时重开不出窗口；开启时完整重开只启动一次，手动停止后改参数不自启 |
| 切为无 / 停用 / 正常退出 | 主题恢复，本轮源窗口和采集消失；原 WE 身份及桌面壁纸保留 |
| 初始屏幕外 | 如已实现，单独记录是否减少闪窗、是否持续出帧；无法消除闪窗作为限制记录 |
| 恢复 | 备份后外部安装；结束恢复本轮起点 Profile 与外观，保留测试后数据，再由用户确认 |

长时验收主要用一个连续会话，穿插必要的缩放 / 最小化 / 输入观察；通过后不重复跑同样的 35 分钟。
异常或清理未确认时先停在现场证据与修复，不用更长运行掩盖问题。
