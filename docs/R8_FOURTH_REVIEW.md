## F2：“32 次写入没有落后”不能排除更新间隙（P1）

108 行 hook 只记录写入时间和值，242–253 行再配到最近之前（允许 +0.5ms）的 RAF 样本，没有在写入当时读取应有几何。写入值正确也不代表从滚动发生到写入之间没有旧值，更不代表合成器实际使用了该值。一个收到事件后才补上正确值的实现，写入检查仍可全为正确。

所以报告里的“裁剪始终正确”“滞后与旧帧都不是原因”“16 个样本只是采样顺序假象”都超出了证据。应改为：写入记录未检测到计算值落后，绘制帧仍出现越界，主线程/合成器使用状态的关系待区分。

frame-pairing 仍按绝对差选最近样本，可能选到帧生成后的状态；例如 frame=108、samples=100/110 会选 110。这可以保留为明确标注的近似配对，不能用未来样本否定早先画面，也不能把平均 1.44ms 当实际画面归属已验证的误差。

## F3：传输延迟校准仍混用起点（P2）

frame-pairing.mjs:42 的 deliveredAtEpochMs - generatedPageTime 又是 epoch 减页面相对时间。实际报告 minOffsetMs 接近 performance.timeOrigin，表示这个数字没有减掉 origin，不能用它检查真实传输延迟或提前到达。

保留 generatedAtEpochMs 或传入 timeOrigin，计算 deliveredAtEpochMs - generatedAtEpochMs。人工回归应使用真实同一 epoch 的数值：提前超过舍入容差必须被识别，正常延迟应返回小的毫秒数。把过去/未来样本区别和原始数据保留在诊断结果中；不为这个补完而延误固定区域的修复循环。

## F4：目录回归没有失败断言（P2）

temp-profile-boundaries.mjs 的 refuses 会记录 NOT-REFUSED，junction 创建失败会跳过关键测试，最终只打印结果，仍 exit 0。正常路径布尔值为 false 也不会失败，无法作为自动回归门槛。

加 assert/非零退出与明确预期错误检查。所有合成目录用 mkdtemp，不用 Date.now + mkdir 复用旧目录；只清理本次精确登记、解析边界已验证的目录，先解除本次 junction，finally 恢复环境和时钟。不要把正常拒绝也当通过、吞掉 setup/cleanup 失败。此次未运行这个脚本，而是使用独立带断言、保留证据的安全合成检查，结果见证据目录。
