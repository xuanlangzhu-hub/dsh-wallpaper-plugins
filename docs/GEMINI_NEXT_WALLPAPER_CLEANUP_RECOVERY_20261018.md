2. **建立独立恢复入口。** 缺Summary时，首次停止和后续重试可以有界地取得新的可信状态，不只等待原管道。底层系统IO可替换，真实默认解析/身份判断必须经过测试；不得整体替换核验器为“成功”对象来证明生产解析通过。旧记录只作关联线索，关键结论来自可验证的当前状态或严格绑定的终结证明。
3. **按顺序收尾。** 只有确认本轮采集和worker不会再操作源窗后，才允许核验/关闭本轮源窗；源窗确认为无残留后释放session和操作锁。PID复用不能对新进程发动作；若据此推断原实例已退，也须说明证明规则并完成其它资源核验，不能一项变化就跳过整个收尾。
4. **失败可重试，成功真正释放。** 未知时保存身份/归属与明确原因；条件解除后再次核验能够成功，清掉对应的旧cleanup错误。Host status与界面应恢复可开始/重启；不能仅改前端disabled或强制丢弃session。重复stop、并发重试及旧轮迟到结果不得影响新轮，也不能留下重复timer/listener。

## 验收矩阵

先把旧缺陷回放改成面向正确行为的失败用例，再实现修复。回放输出写本轮独立目录，不改/覆盖旧证据。

| 场景 | 必须观察到 |
| --- | --- |
| 正常终结Summary齐全 | 正常停止、清理和释放保持；不引入不必要的常态重查询 |
| 正常退出但无Summary | 首次仍未知时保留；后续取得独立终结证明后可收尾，不永远等待旧流 |
| 超时强制/异常退出且无Summary | 同样经历未知保留→重新核验→合法条件解除后成功，不能仅凭child退出判全局安全 |
| worker仍活或仍可能操作源窗 | 不提前关闭源窗，不释放锁，不开第二轮 |
| PID被复用、身份字段缺失/损坏、查询错误/超时 | 不对陌生/未知进程发动作；不报告假成功；证明不足保留，错误可解释 |
| worker安全但源窗关闭失败 | 保留本轮归属；重试最终确认源窗无残留后再释放 |
| 状态/动作文件来自旧代次或旧身份 | 不被用作本轮终结授权 |
| 重复/并发stop和恢复后重新选择/开始 | 清理幂等，无重复监听/timer；无session-busy旧锁；旧轮迟到结果不污染新轮 |
| 原WE主进程与其它轮资源 | 零非本轮终止/关闭动作，未动原WE |
