# 作者设置 P1：正式controller、双端详情表单与当前壁纸应用链

2026-10-21。先读[P0交付](WALLPAPER_AUTHOR_SETTINGS_P0_DELIVERY_20261021.md)及实际源码/QA。日常DSH0.2.1-rc.2/外观rc.42/Git Bash0.1.1保持，先离线，不整包开发树、不安装或开真实窗。

## 产品目标

在既有壁纸预览/详情中，当前所选壁纸下显示作者自己的参数。主侧栏和独立窗共享数据、约束和交互；分组/说明项作为结构而非可调开关。大量参数需要清楚的分组、搜索/折叠和留白，沿用现有主题，避免把通用设置长表原样塞入详情。明确区分作者默认值、插件草稿、已发送至当前壁纸；不得把前者显示成已读取WE当前值。

## 首先接正式认证和唯一状态

1. 将P0服务接现有唯一controller和主端/伴随窗认证，复用会话/lease/主代次校验。P0 readContext是必须由真实Host填充的认证钩子，不接受前端声明authorized/owner/分级/所选ID/活动窗口。不能注册无认证的新loopback入口。
2. 分级策略收紧、选中ID、主端重注册、lease过期、停止/卸载、活动会话/窗口代次变化后，旧请求拒绝且不重建草稿。控制器销毁时调用dispose/clearOwner，等待/报告必须有限。不要把“拥有一个合法旧token”当成当前会话仍有效。
3. 正式静态文件仅加入已审浏览器共享契约及其导入闭包，校验主端注入、独立窗生产静态加载、路径和包导入闭包；不开放任意文件路由，不将Node schema/Host模块发给浏览器。

## 双端表单

沿用P0 schema、修订和表单ticket/pending增量机制。支持bool/slider/color/combo及有限textinput；empty与unsupported区别显示。unsupported-condition不eval，先明确未支持。切换B仍播放A时仅编辑B草稿，应用动作只允许当前活动同ID；隐藏分级不读其属性/预览。修订冲突提示刷新并保留未提交修改，明确恢复作者默认与普通保存不同。

真实应用链尚未通过前，控件编辑必须表明是草稿，“应用到当前壁纸”保持禁用或清楚标明未接通，不假称即时生效。接通后再做有界合并/节流与失败回显，不能每次渲染发命令。

## 应用链单独受审

P0 plan只生成参数数组，不能把planOnly改个标志就当执行完成。若本阶段接adapter，必须限定可信WE可执行文件、当前活动ID/同轮location/PID/启动时间与停止代次；始终用参数数组，RAW分隔符与JSON约束保持。禁止省略location、全局属性更新、任意前端JSON/path/window target、改源project.json或原桌面WE设置。

命令前后重验身份及代次，停止/卸载取消迟到结果，命令/退出确认有总期限，只收束本轮自有命令进程，不能杀原WE。ASCII与Unicode属性值的传参边界须分别说明；不改系统代码页或照搬MP4副本桥处理网页/配置。发送成功仅称“已发送”，作者代码是否响应、音频/交互和当前值回读须另取证。
