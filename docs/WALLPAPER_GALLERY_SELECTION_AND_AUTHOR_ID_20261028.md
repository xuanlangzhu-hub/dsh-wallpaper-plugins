## 本轮交互合同

- 图库中的“返回”改为“壁纸参数”，点击后进入详情；详情里的“更换”保留。
- 点卡片只更新选中项，保持图库、搜索和分页位置，不播放、不停止、不自动跳到参数页。
- 主按钮显示图标加“播放／停止”文字。播放 A 时选择 B，A 保持播放，点击 B 的播放后才切换；这时另有“停止当前播放”入口。
- 切换调用已有 controller.restart，由真实 Host 先核验 B，再确认 A 清理，最后启动 B；不能用前端自行 stop→start 两步绕开所有权与清理证明。
- 同一时刻重复点击被锁住；选中项、模式、活动源／generation 变化时，旧按钮事件拒绝执行。B 不可用、清理未确认或状态未知时不启动 B。

## 作者参数归因与修改

按实际 rc.52 客户端和共享侧栏源码建立对照：

1. 前端硬编码成立：authorContext 要求 selectedId／activeId 都等于 lucy；schema、草稿、应用及恢复请求固定发送 lucy，并只接受 Lucy schema。
2. 后端并非只接受 Lucy：库按受控 ID 重验元数据，schema 支持 scene／web，Host 和 ApplyAdapter 验证选中 ID、活动 ID、generation 与同轮身份。实际库／Host／重启相关 58 项受控回归通过，不能因此扩称真实窗口验收。
3. 壁纸不提供参数／参数类型不支持仍是独立情况。空公开声明应成功返回空结构，不能伪装成读取失败；video 仍不进入 scene／web 作者参数路由，条件参数和既有不支持类型不在本轮放开。

前端现在将正在播放且符合分级／类型的同一壁纸 ID 传给作者模型。模型把 ID 固定到每个任务，所有 schema／草稿／apply／恢复请求沿用它；返回 schema 必须匹配，ID 变化即使复用上下文键也取消旧任务并重置状态。生产 provider 总是显式传 ID；旧单参数 setContext 的 Lucy 默认仅保留既有调用兼容。

自动读取仍只在合格的正在播放详情可见时执行，不在图库轮询、不代替用户播放或默认下发参数。读取的是公开声明中的默认值／本机记录，**不是从 WE 抓取当前实时参数值**。本轮没有把非 Lucy 加入自动播放名单；该名单仍只有 Lucy。

## 切换响应补严

SDK 的异常响应对照暴露旧 restart 仅检查 HTTP 成功状态：若误回 HTTP200 而正文明确 ok:false／cleanup.closed:false，会被当作新连接。原负例见 focused-windows-flow-v3-report.json。

客户端 restart 增加一个拒绝条件，明确失败或清理未确认即使返回 2xx 也保持失败，不接通 B。最终 SDK 分别验证真实 Host 协议的 409 失败与 200 异常正文，A 保留、没有补发 start，用户显式停止可恢复。其它客户端业务代码保持；Host 原有核验、所有权、原生身份门禁没有放宽。
