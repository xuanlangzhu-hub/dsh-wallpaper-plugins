## 1. 一句话方向

**像 DSH 自带的一块外观工具栏：看得见正在调哪张壁纸，伸手就能调，调完继续聊天。**

壁纸承担画面和个性；工具本身安静、清楚。采用原生最右侧栏、现有主题和字体、小面积强调色、对齐的表单行。这里不需要独立应用的首页、大标题、宣传文案或一排统计卡片。

“简约”具体指：减少同时出现的决策，保持操作位置稳定，把状态放在对应控件旁；不是把按钮全换成无标签图标，也不是把所有功能藏进“高级”。

## 4. 页面骨架与常驻区域

只保留两个一级分区：**壁纸、界面**。图库是“壁纸”的子视图，不再加第三个一级 Tab。宿主已经有页签标题与关闭行为，插件正文不再重复一个“Whale 外观”大标题或关闭按钮。

### 4.1 壁纸详情

以下是约 360–420 CSS px 宽的布局示意，不是截图。符号代表控件角色，不要求直接使用这些 Unicode 字形。

```text
┌─────────────────────────────────┐
│ 壁纸                     界面   │
├─────────────────────────────────┤
│ [小预览] Lucy                   │
│          播放中                 │
│ [停止播放]     更换壁纸      ⋯   │  ← 固定对象区
├─────────────────────────────────┤
│ 壁纸设置                    ⓘ   │
│ 粒子                     ✓ [开] │
│ 光照                       [开] │
│ 水袋                       [开] │
│                                 │
│ 画面                            │
│ 亮度                       80%  │
│ ─────────────●────────────       │
│ 遮罩                       30%  │
│ ───────●──────────────────       │
│ ▸ 更多画面选项                  │
│ ▸ 播放选项                      │
│ ▸ 本壁纸外观预设                │  ← 正文独立滚动
└─────────────────────────────────┘
```

- 小预览沿用现有安全资源，72×约 41px 足够；不做大幅封面、实时画中画或自动播放的预览。原图缺失时保留小块中性占位，不用醒目的错误卡片。
- 标题最多两行，固定对象摘要区不会因选中和播放切换持续跳动。完整标题在可键盘访问的详情中查看；`title` 只是辅助，不能是唯一方式。
- 顶部明确显示**活动对象**；没有活动对象时显示所选对象。预览和标题必须来自同一个经确认、通过分级的对象。身份未知时显示“壁纸状态待确认”，不借用所选项图片装作仍在播放。
- 主操作有文字；“更换壁纸”是低强调的文字按钮，`⋯` 有“壁纸更多操作”的可访问名称。没有可用次级项时不画空菜单。
- “停止播放”是日常主操作，不用危险红色。故障恢复需要的检查清理放到主操作位，不能藏在更多里。
- `关闭背景`放入更多：它停止／关闭当前背景并退出该背景来源；`停止播放`仅结束这一轮，保留所选来源。这两个行为不能合并成一个开关。
- **顶部停止始终可达**：进图库或切“界面”仍保留固定对象区；可收紧空隙，不新建第二个播放按钮、不重建正在处理的命令。
- 正常高度下，固定区尽量控制在 150–180px 内；这是布局目标，不是裁切规则。长标题、缩放与异常优先完整可用。极矮窗口允许插件自身整体滚动作为降级，不能把主控挤出、让正文高度为负或改宿主滚动。
- 作者参数保留作者排序，默认展示当前可操作项。数量过多仍使用正文滚动，不随意判断哪些作者参数“不重要”、裁成前三项。

### 4.2 界面分区

```text
│ 壁纸                     界面   │
│ [当前对象与播放主控仍可达]       │
├─────────────────────────────────┤
│ 主题与配色                      │
│ 主题                 [鲸渊 ▾]  │
│ 深色配色             [深海 ▾]  │  ← 仅适用时出现
│ 强调色           [跟随主题 ▾]  │
│                                 │
│ 文字与底色                      │
│ 文字可读性           [增强 ▾]  │
│ 聊天底色                   50%  │
│ ──────────●───────────────       │
│ 界面不透明度               70%  │
│ ───────────────●──────────       │
│ ▸ 更多外观                      │
└─────────────────────────────────┘
```

最终使用统一的自绘下拉选择器，触发框与展开列表一起跟随主题，见第 6.5 节。D1–D3 先保留已有 select 完成反馈和层级，D4 再替换，不能把过渡状态当成最终交付。两选项不必全部改成分段按钮，主题也不做巨型缩略图。自定义强调色选中后才在这一项下出现色块与色值，不给其他用户留空位。

### 4.3 图库

固定对象区保留；下方是“返回当前壁纸”、搜索框、三分级复选框、预览网格、按需分页。每个分级文字可直接点击，不藏进筛选抽屉。默认只选全年龄；沿用用户已保存的明确选择。

卡片只保留预览、两行名称、一行类型；选中靠固定位置的勾与边框，实际播放才标“播放中”。不加播放悬浮按钮、下载数、随机推荐、评级、收藏占位或标签云。无预览不等于不可播放，能力由现有数据决定。

正常宽度两列，内容区小于 288px 改一列；不在窄栏挤三列，不靠缩小字体塞下内容。12 项分页和有界预览队列保持，先不改无限滚动。当前可用列表为空时，区别“目录读取失败”“搜索无匹配”“未勾选任何分级”；只有读取失败提供重试。

**选择只保存选择，不能暗中开始／停止。** 已播放 A 时选 B，回详情后仍显示 A 的活动摘要，增加一条“已选：B”，主操作仍为“停止播放”；等停止确认后，主操作才变成 B 的“开始播放”。此时作者参数不向 A 或 B 偷发，保持现有资格门禁。这条少一次点击的优化以后若做，必须独立设计生命周期，不能混进 UI 重排。

## 5. 控件位置与显示条件清单

| 控件／能力 | 位置与默认状态 | 必须保留的实际范围 |
| --- | --- | --- |
| 当前壁纸、开始／停止、更换 | 固定对象区，主路径直达 | 只反映 controller 状态；启动、停止、清理不能由显示条件猜测 |
| 关闭背景 | 对象更多菜单 | 保留关闭证明和恢复门禁；必要的“检查关闭”异常动作必须外露 |

| 亮度、遮罩 | 壁纸正文“画面”，常显 | 20–120%、0–90%；范围和保存规则不变 |
| 背景模糊 | “更多画面选项”，默认收起 | 0–24px；只影响背景 |
| 播放模式、随 DSH 启动自动播放 | “播放选项”，默认收起 | 日常／限时预览；仍只允许满足资格的 Lucy 自动播放；关闭旧开关的通路保留 |

| 本地图片／视频选文件 | 对应来源详情，选择／更换可见 | 取消选文件不变更；现有格式／大小／缓存租约限制不变 |
| 本地媒体移除 | 来源更多操作 | 仅移除插件已存媒体，不删除原文件；不要另造“删除文件”文案 |
| 本地视频播放策略 | 本地视频详情的“播放选项” | 失焦暂停／始终播放沿用；隐藏、最小化和减少动态的现有限制仍生效 |
| 主题、深色配色、强调色 | 界面“主题与配色” | 主题为鲸雾／鲸渊；深色配色仅鲸渊；保留自定义强调色 |
| 文字可读性、聊天底色 | 界面“文字与底色”，常显 | 标准／增强；底色 0–100%，不伪称整体画面对比度 |
| 界面不透明度 | 同上，常显 | 40–100%；输入区／菜单现有不透明边界不变 |
| 左侧栏实色底 | 界面“更多外观”，默认收起 | 仅有背景时适用，指左侧项目／会话栏；不是右侧工具栏开关 |
| 侧栏层次、背景层次、玻璃强度 | 同一个“更多外观”内顺序排布 | 均衡／稍深、柔雾／清晰、标准／克制；不改 CSS 投影业务 |
| 重新读取作者结构／记录 | 作者组首次加载入口；加载后降为次操作 | 不读取 WE 实际值，不重新下发；D1 只改呈现，暂不增加自动 load |
| 未支持的作者项 | 首屏不画不可用输入；若现有数据可安全展示，放按需说明 | 条件表达式、未知类型不能自己解释或执行；D1 不增 schema 能力 |
| 诊断、原始错误、未知恢复 | 只在相关故障处出现摘要，详情按需展开 | 必要的观察／确认／清记录不藏掉；不恢复全局重试或清理按钮墙 |
| 外部独立窗口 | 本轮不增加常驻入口 | 将来作为可选能力；弹出成功收起侧栏编辑区，关闭未确认不允许双入口写入 |

本地来源与 WE 来源的统一选择器需要额外注意：目前不是任意两种来源都能直接切换。**D2–D4 不把它们画成可任意点选的四段开关。** 先重排已有、满足能力条件的选择／关闭入口；更顺滑的跨来源向导若要做，单独列行为任务，先明确停播／关闭／取消／失败状态。不要为了好看接一条绕过门禁的新 `set(background)`。

## 6. 控件设计规范

### 6.1 对齐、尺寸、材质

- 正文横向 16px；分组间 24px，组内普通行 12px，标签和输入 6–8px。已有 20px 间距可在对应分组任务内统一，不做全仓格式改动。
- 普通按钮、下拉、文本输入最低 32px；常用表单行约 36–40px，可随字体与多行内容长高。图标点击目标 32px，图形约 16px；别把点击区缩成图形大小。
- 全局继承字体。正文 `1em`，辅助说明约 `.875em`、通常不低于 12px，标题约 `1em/600`。尊重宿主字体缩放，不通过 `font-size:12px` 压缩整个面板；数值使用 tabular-nums。
- 标签左对齐，数值右对齐，范围控件在下一行占满可用宽度。长标签可换行，开关和状态槽不被挤小；不让字段名被单行省略到无法分辨。
- 控件圆角 6px，预览 4–6px；分组不用圆角卡片包裹。只有区域边界需要分隔线，普通字段行主要靠间距区分，不一行一道线。
- 正文透明度沿用现有宿主／主题投影；输入和菜单保持已有可读底色。不叠新的玻璃模糊层、渐变蒙版或整页固定底色。不要对整个组设低 opacity 连带削弱文字和焦点。

| 视觉角色 | 既有 token／来源 | 使用方式 |
| --- | --- | --- |
| 正文 | `--dsw-alias-label-primary` | 标题、标签、当前值 |
| 次文字 | `--dsw-alias-label-secondary` | 类型、帮助、非错误的来源说明 |
| 线条 | `--dsw-alias-border-l2` | 区域边界、输入边框 |
| 控件底 | `--dsw-alias-button-elevated-fill` | 输入／必要次按钮；正常内容不另铺卡片 |
| 主操作 | `--dsw-alias-button-primary-fill`、现有主按钮前景派生值 | 唯一开始／停止／恢复动作，保留自定义强调色对比逻辑 |
| 选中、焦点 | `--dsw-alias-brand-primary`、`--dsw-focus-ring-color` | 小范围强调，不把整个面板染色 |
| 错误 | `--dsw-alias-label-error` | 确定失败；未知状态用明确符号和文案，不凭空引入黄色色板 |
| hover／pressed | `--dsw-alias-interactive-bg-hover`／`active` | 就地反馈，不位移、不放大 |

本次刻意不新增六个写死色值。浅色、深色、自定义强调色都来自现有 token；失效 token 必须先查明再用，不能新增全局别名掩盖。样式范围只限 Whale 根节点或明确标识的入口。

### 6.2 五类作者控件

| 类型 | 外观与提交 | 取消／错误 |
| --- | --- | --- |
| bool | 标签左、固定反馈槽、右侧开关；保留原生 checkbox 的键盘和表单语义，可用局部样式做开关外观 | 点击只产生一次 change；开关位置是参考／请求值，不代表读回；不再以初始 indeterminate 画减号 |
| slider | 标签＋右对齐值，下一行滑轨；已有数值输入保留，可精准调节 | 沿用拖动完成、键盘提交与取消规则；不逐像素启动命令，也不新增无限 debounce |
| combo | 标签与统一自绘选择器，D4 前用原生 select 过渡；小选项集合仍用同一组件 | 只提交真实 option 值，选项文案不能替代 bool／number 类型值 |
| color | 标签＋色块和十六进制值；已有 RGB 精调放本项的具名折叠区 | 复用现有颜色转换／提交链；不在 UI 偷加 alpha；无效输入不下发 |
| textinput／数值编辑 | 标签和正常输入框，有效完成后提交；不用单独“保存” | 保留 IME、Enter、blur、Esc、编辑票据；Esc 只取消未提交编辑，不声称撤回已发命令 |

D1 先统一反馈，不同时做开关换皮、RGB 折叠或输入布局重构；这些在 D4 做。默认保留已有输入精度／min／max／step，不凭习惯加 `%`。作者 slider 的单位只有明确来源才显示。

插件自身亮度、底色等同步 CSS 控件与作者远程命令不是同一类：前者拖动直接呈现已有本地更新，不必显示“下发✓”；后者有真实命令流程才使用下面的状态槽。不要为了组件统一，给每个本地滑块也加等待和成功提示。

### 6.3 固定反馈槽与来源说明（D1 的核心）

每个作者字段预留约 18px 宽的反馈槽，与标签／主控基线对齐；空、忙碌、确认和异常占同一宽度。五种状态采用已有图标资源或小型本地 SVG，不引入图标库。状态不会改变控件宽度、推动值、让整行闪烁。颜色的 RGB 子输入和滑块附带数值框共享父字段的一个送达状态，不各自重复三个✓；各自的格式错误仍就近表达。

| 真实状态 | 可见呈现 | 可访问说明／详情 | 不能做 |
| --- | --- | --- | --- |
| 无 mark | 槽为空，显示作者默认值或插件记录 | 分组标题旁“数值来源”帮助：`显示作者默认值或本机记录，未读取壁纸实际值。` | 初始给所有字段打✓；把 bool 变成第三态 |
| busy | 静态省略号／处理中符号，控件保留用户请求位置 | `正在处理修改`；可能排队，不统一说“正在发送” | 提前显示成功；在 UI 加一个独立超时放开写入 |
| sent | 小号✓，不强制绿色 | `下发已确认，效果请观察` | 说“画面已同步／已生效”；通过记录 confirmed 重建永久✓ |
| error | 字段旁错误标记，组内或字段下短原因 | `修改未完成`加可确定原因 | 把失败一概说成输入非法；自动翻回开关表示已回退壁纸 |
| unknown | 字段旁待确认标记；组内一条可见摘要 | `本轮修改结果未确认`；必要时引导观察和现有恢复 | 声称每个同标字段都发送了；给每字段一个重试 |
| 本地格式错误 | 对应输入错误边框＋就近说明 | `aria-invalid`只用于值格式／范围等真实校验错误 | 与命令结果 unknown 混为同一种表单错误 |

说明帮助必须能通过点击或键盘打开并关闭；不能只靠鼠标悬停和 `title`。优先现有 `details/summary` 或已核实的局部组件，不为一个帮助气泡引入组件库。成功状态不抢焦点，不每次播报长句；异常区域复用一个受控的 live region，避免五个字段同时大声宣布同一条 unknown。

**D1 不加短暂✓倒计时。** 当前 mark 会在下一次变更、重新读取或失去上下文后清除，就按真实生命周期显示；用小号、低强调减轻干扰。将来如需淡出，只能另作展示层变动，不得清掉业务 mark 或用计时器推断成功。

当前 timeout 会把排队字段也标 unknown，而其中部分可能没发送。字段符号表示“受本轮未确认操作影响”，详细恢复以分组为单位。[审计报告](WALLPAPER_NATIVE_AUTHOR_FEEDBACK_AUDIT_20261025.md)中的两个观察必须原样作为验收边界保留。

### 6.4 按钮、折叠、反馈文字

- 主操作保留明确动词：开始播放、停止播放、检查清理。若同一状态已有主按钮“正在清理…”，旁边不再重复一段相同“正在清理”。异常原因则仍可见。
- 正常成功不弹 Toast、不追加日志列表、不出现“草稿已保存／参数已发送”的常驻段落。已有预设成功小标记可以保留，不能混成作者视觉确认。
- 首次作者读取保持明确“读取壁纸设置”；读出字段后用低强调“重新读取”，帮助写清“读取设置结构和本机记录，不读取壁纸实际值，不重复下发”。编辑中保持“取消编辑并重新读取”的真实含义。D1 不新增自动读取。
- “更多画面选项”“播放选项”“更多外观”“本壁纸外观预设”均直接由标题行展开，默认收起；不把它们再套进一个总“高级设置”。既有预设的覆盖／删除确认保持，不为所有普通调整增加确认框。
- 折叠是视图变化，不写新设置，不取消已发出的物理命令。若内容有未完成文本编辑、焦点或错误，不为整齐强制折叠；实现者需先复用既有编辑边界，不能靠卸载 input 偷触发 blur 提交。
- 初始折叠状态只在面板实例保留，不为了记住每个展开状态新增持久化字段。错误涉及收起组时，组标题要有明确异常标记和可打开的短提示，不能把问题一起藏掉。

### 6.5 控件本体与下拉展开层重做（用户同日补充）

**决定：改控件外观，也改下拉列表本身。** 只给 `<select>` 的外框换圆角和背景不能保证展开列表统一；当前源码仍使用 `<select>/<option>`，现有 `color-scheme` 等局部规则不等于完整的下拉视觉组件。这是静态代码判断，本轮没有打开桌面重新观察弹层。

整体做成轻量桌面控件：细边界、清楚的选中状态、少量圆角、足够点击区。不是把每个控件都做成胶囊、发光按钮或大块玻璃卡片。

| Before | After | Why |
| --- | --- | --- |
| 下拉外框有主题，展开仍可能是系统列表样式 | 一个共享选择器统一触发框、列表、选中勾、hover、键盘焦点和禁用项 | 控件展开后仍像 DSH 的一部分 |
| 布尔控件统一显示默认小方框 | 立即启用／关闭的功能用紧凑开关外观；年龄多选、确认清记录保留方形复选框 | 区分即时状态与“选择多项／确认”，不机械把 checkbox 全改成开关 |
| 滑块轨道、滑块头和输入边框各用默认外观 | 统一细轨道、适中滑块头、同组对齐数值；输入框共享边界和焦点规则 | 参数区有秩序，视觉安静而不是缩小到难操作 |
| 所有按钮几乎同等显著 | 主按钮、次按钮、无边框文字入口三种样式 | 主要操作突出，其余不会争抢注意力 |

**下拉触发框**：最低 32px 高，6px 圆角，左右 10px 内边距；当前值左对齐，末端固定 16px 下拉箭头。默认低对比边框，hover 提亮局部底色，focus-visible 使用统一焦点描边。禁止厚重立体边框、渐变高光和宽大的三角按钮区。长值可省略，但展开列表能读到完整文本。

**展开列表**：与触发框至少等宽，在可用空间内定位；默认向下，空间不足向上，不超出可视区域。约 4px 间隔、6–8px 圆角、4px 内边距，选项最低 32px；最多约 240px 高，更多选项在列表内滚动，行内文本可换行。轻边框和一层很淡的阴影足够，沿用既有弹层材质，不额外堆模糊特效。

列表背景采用已有**可读的菜单底色**，不跟随侧栏透明度降到看不清；文字、强调色与浅深主题同步。这沿用“侧栏可半透明、菜单保持可读”的既有语义，不另造一套固定配色。选中项使用固定勾选槽＋轻底色，hover／键盘浏览是另一个状态，不能都画成“已经选择”。禁用项仍能读懂名称与原因，不只把整行 opacity 降到近乎消失。

**键盘和提交规则**：

- 设置值的选择器使用可访问的 combobox／listbox／option 语义，不把它当动作菜单；`⋯` 中的关闭、移除等是另一类动作菜单。
- Enter／Space 或方向键可打开；上下键浏览，Home／End 到首尾，支持按文字定位选项。Enter／点击选项才确认一次选择；打开、浏览、悬停、定位不调用设置 API。
- Escape、点击外部或 Tab 离开取消未确认的浏览，不提交；Escape 收起后焦点回触发器，Tab 正常移到下一项。已确认同一值不重复提交。
- 保持可访问名称、当前值、展开状态、活动项和选中项可读；不要同时保留两个能被键盘聚焦或被辅助技术读到的重复选择器。
- 按原类型传回 option 值；作者的 `false`、`0`、字符串 `"0"` 必须可区分，不统一转成字符串再猜类型。
- 目标／代次／可编辑资格在展开期间变化，撤销旧选择上下文，关闭列表且不提交。选项在点击前被移除或禁用也不能继续提交旧值。

**承载与生命周期**：优先复用已核实、能继承主题且满足键盘行为的宿主／仓库组件。如果没有，再实现一个小型局部选择器供所有设置复用；不要为十个字段各写一份，也不要为下拉一项导入整套 UI 框架。新选项列表必须在侧栏 `overflow` 下不被裁切；使用已验证的弹层层级或带 Whale 标识与主题 token 投影的专属 portal，不靠全局 `z-index:999999`、改 `body` 样式解决。portal 的指针事件范围、滚动、主题更新、焦点和回收须明确，不能覆盖聊天区截获无关操作。

一次只展开一个选择器；切换页签、隐藏／关闭侧栏、目标失效、卸载时关闭并释放自身监听／定位观察器。更换焦点不能触发旁边尚未完成作者输入的意外 blur 下发，仍需遵守现有编辑票据和可见性边界。

**其他控件**：开关可采用约 30×18px 的细小轨道和清楚的滑块位置，点击行仍至少 32px，颜色之外靠位置表意；年龄分级和恢复确认保留约 16px 的复选框与整行标签点击区。滑轨约 3–4px、滑块头约 12–14px，实际拖动命中范围至少 24px，指针和键盘都能精准操作。文本／数值／搜索框共享 32px 高与 6px 圆角，错误说明只在需要时出现；数值输入保留键盘增减和真实 step，不能删掉精确调节能力只剩装饰滑轨。这些尺寸为 CSS px 设计起点，宿主字体缩放优先，不裁切文字。

**实施切分与验收**：D4a 统一按钮／输入／checkbox／switch／range 表面样式；D4b 单独完成共享选择器及一个低风险界面字段，再逐项接入其余界面、播放和作者 combo；D4c 才整理图库细节。每步交付，不一次性替换所有交互。D4b 属于组件交互替换，必须覆盖键盘确认／取消、外部点击、上下定位、窄栏、高缩放、滚动、不重复提交、原类型值、迟到和卸载；测试改用真实角色／可访问名称和值，不只改断言让旧 selector 变绿。实际展开列表仍需后续候选视觉确认。

## 7. 完整交互与特殊状态

| 用户动作／状态 | 用户能看到什么 | 实现约束 |
| --- | --- | --- |
| 打开侧栏 | 当前对象＋明确操作；已有数据可用就直接展示 | 不自动播放、改变分级、重放作者设置；沿用已完成的目录 ensure |
| 作者初次没有字段 | 一个读取入口；不摆空开关和三按钮链 | 保持当前显式读取流程，后续自动读取须单独立项 |
| 修改作者开关 | 当场变位，槽进入处理中，然后给确认或异常 | 显示的是请求值；等待期间可否编辑由现有 canEdit 决定 |
| 快速修改多个参数 | 对应行有状态，不出现多个全局通知 | 保留单执行器、合并／排队和迟到结果围栏 |
| 停止／切目标／切会话 | 主控状态持续可读，旧编辑与成功标记不迁移 | 旧值不得套给新目标；隐藏／卸载不自动提交未完成输入 |
| 关闭、隐藏、切到宿主其他页签 | 聊天界面正常使用 | 面板消失不等于停止壁纸；不为外观导航新增 start／stop |
| 等待物理命令结束 | 保留忙碌或待确认反馈，不能重复发 | 到 UI 截止时间不等于底层进程退出；恢复按钮由现有能力提供 |
| 清理失败／关闭未知 | 顶部短原因＋真实可用的检查动作 | 不显示“未播放”掩盖残留，不开放切换来绕过清理 |
| 作者恢复记录 | 一条明确问题摘要，展开现有观察／清记录流程 | 观察确认、旧结构辨认和清记录不回退壁纸的说明必须保留 |
| 保存／恢复外观预设 | 标出四项范围，再执行已有动作 | 不悄悄保存全部作者参数；覆盖／删除的确认必须匹配当前目标 |
| 无适用功能 | 不出现该组；用户主动进入相关入口才解释限制 | 不给未实现的 reset、收藏、随机播放占位 |

错误文案采用“实际问题＋可行动作”，例如“目录读取失败　重试”“修改结果待确认　查看处理方式”。仅在操作确实可安全重试时出现重试；未知命令不是这种情况。原始错误码、PowerShell 命令、路径、堆栈留在详情／已有诊断材料，别直接填满侧栏。清记录会做什么仍须明说，不能把重要差异藏在技术详情里。

**首次读取是过渡流程，不是最终理想。** 更自然的终态是：合格活动壁纸的设置在打开对应详情时自动出现，不要求用户先理解“读取”按钮。它需要独立的只读生命周期任务：仅在目标／代次／可见性合格时进行一次有界 schema 与本机记录读取；失败才显示重试，不轮询、不 apply、不因旧记录恢复重放，隐藏后迟到结果丢弃。D1–D4 不做；可在 D5 中另开一个小任务，确认请求数和恢复边界后再实施。若没做，就明确保留首次读取入口，不能用加载动画假装已有自动读取。

## 8. 作者标签与内容安全

- 已有 schema 会尝试作者本地化表，再使用回退标签。先用这个真实来源，不根据截图或猜测将 `ui_...` 改成看似合理的中文。
- 已确认的 `粒子/Particles` 这类双语名可以通过**经过核对的显示映射**简化成“粒子”，完整原名在详情可查；不写一个按 `/` 一律截断的规则，斜杠可能属于真实名称。
- 未解析的 token 可在后续 D5 采用“未命名设置＋稳定序号”的可辨认占位，并提供原始名称详情；仍不能猜它是主题色或音量。D1 只保留现有标签，不混入这项处理。
- 现有 Host 未提供的信息不要由前端扫 project.json 补齐。若标签改善需要 schema 字段扩展，D5 必须另列 Host／契约变动和测试，不能冒充只改文案。
- 作者 metadata 只作文本处理，不执行 HTML、脚本、条件表达式或任意 URL；长名称正常换行，无有效标签时仍能区分不同字段。
- 分级过滤先于标题、图片、无障碍名称、搜索结果、tooltip 和请求资源。隐藏的成人内容不能通过当前对象摘要或“所选：”泄露；分级取消时撤下对应资源，不自动停播／改选别的壁纸来制造“安全成功”。
- Unknown 分级不展示；三分级全取消是明确空选择，不能擅自重新勾选全年龄。搜索、分页、切主题均不得重置用户分级选择。

## 9. 响应式、键盘与动效

最少覆盖 320／360／520 CSS px，以及实际宿主允许的更窄宽度、200% 缩放、长中文／英文名称和高对比环境。用容器实际可用宽度布局，不按整块屏幕宽度判断侧栏宽窄。控件不溢出，不横向滚整页；原生命令与文件页的滚动不能受影响。

Tab 顺序跟随视觉顺序；分区沿用左右方向键／Home／End；自绘选择器按第 6.5 节实现完整键盘交互，checkbox、range 保留原生键盘能力。折叠和菜单关闭后焦点回到入口；busy、确认标记和新错误不自动抢焦点。不支持的控件不堆在键盘路径里，临时禁用的必要操作要有可发现的原因。

动效本轮采取克制默认：按下用局部底色变化；选中、标签、值不做弹跳／缩放／逐项入场；不在每个处理状态挂旋转动画。已有宿主侧栏开合由宿主负责。D1 不增加动画／定时器；后续确需小过渡最多考虑 100–140ms 的颜色／透明度，并尊重 reduced-motion。不能用动画延迟真正反馈。

### 实现完的自检问题

1. 不看说明，能否说出当前是哪张壁纸、有没有播放、从哪停止？
2. 普通调节是否一步发生，只有真正必要的异常才要求阅读和确认？
3. 打开界面分区，能否直接找到文字可读性、底色、主题和强调色？
4. 把更多组都收起，首屏是否仍有完整日常路径，而不是一堆空折叠标题？
5. 用亮壁纸、长标题和宽字体时，布局仍然规整，反馈不会挤动控件吗？
6. 每个✓、待确认符号、禁用状态，是否都对应真实能力而非为了“看起来顺滑”？

自然简约以这些实际使用结果判断，不以新增组件数量、动画数量或测试数量判断。
