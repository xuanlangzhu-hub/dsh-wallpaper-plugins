## 3. 下一稿应先修的五点

### R1：恢复当前信息分组，避免拿旧截图当当前规格

当前源码约1917–1934行已将亮度／遮罩／背景模糊置于“画面效果”，界面不透明度／聊天底色置于“界面透出”，都在壁纸页；界面页主要是主题配色、文字和更多外观。

新稿却把两个透明度相关设置搬回界面页，并把模糊藏进“更多画面选项”。这重新引入跨页调整壁纸透出的问题，并非现状的必要延续。主题分段按钮、配色色块、可读性分段也早已存在，图库选中／播放分离在rc.53已完成，不应包装成此次新增能力。

**验收**：以当前源码和10月28日交互成果为基线，保留“画面效果／界面透出”相邻调节。若有确切理由改组，明确画出完整操作路径和收益供用户选择，不静默恢复旧结构。文档区分“已有功能保留”和“本轮新增设计”。

### R2：控件还不够完整，简约不能省掉操作线索

界面板 `9:262` 的滑块表现为细轨道＋填充＋数值框，没有明确拖动手柄；“更多外观”展开后，侧栏层次／背景层次／玻璃强度被并成一行标签和一行取值，三个独立设置的操作目标不清楚。

状态板 `9:412` 主要展示一个下拉及菜单、五态反馈，尚缺开关开／关／禁用、滑块拖动／聚焦、按钮禁用／处理中等关键变体。不能只靠交付文档说“有完整控件”。

**验收**：给滑块可识别的手柄和足够命中区域，画明拖动／键盘聚焦／禁用状态；三项低频设置各自可识别和可操作；补一套小型按钮、开关、滑块、下拉／菜单状态，不要求铺满所有组合。用组件复用统一尺寸、边框和圆角。

### R3：修正失败语义和空反馈槽

状态板中“1项参数未生效”超过了系统能够证明的事实。请求失败或回执缺失，并不总能证明壁纸没有收到；未知状态尤应保留。记录值的“空槽”画成带框的小方块，又容易看成一个未勾选的复选框。

**验收**：依据已知状态分别用“修改未完成”或“发送结果未确认”等短文案，不把错误统一称为未生效。记录值仅保留无边框的布局空间；下发确认的✓只表达协议确认，不承诺实际视觉效果。刷新／重试沿用现有恢复契约，不为简化稿件设计一个无条件重发动作。

### R4：在真实视觉负担下检查材料与层级

全景稿有宿主示意，但中央是大面积设计说明消息；浅色板只展示局部参数。当前背景较暗且平缓，不足以评估白色高亮、花瓣、细密纹理经过正文与关闭态开关时的可读性。浅色“画面与可读性”标题与深色“画面”也没有对齐内容。

**验收**：只选一个常规宽度右栏方案，在暗／明亮复杂背景上各给一张相同布局对照；让正文、开关关闭态、轨道、菜单边界均可辨，菜单允许更实。主题与透明度沿用宿主设置，不单独硬编码一套永远相同的紫色玻璃。无需大量效果图，也不要把透明度越低当作越高级。

### R5：补能落地的少量设计交付

本次目标文件上下文返回组件、组件集、样式和变量均为0，说明目前主要是独立图元，并未形成可复用的小型控件系统；这不代表账号没有其他资源。文档未给背景／缩略图的来源和许可，亦缺交接要求的280–520px适配说明。

现有源码约1291–1310行已有带 combobox/listbox 语义的自绘选择器，不能笼统说整个页面仍在用原生下拉。作者combo／播放模式等个别控件若仍需替换，应逐项确认，设计稿不应指定“藏原select再派发change”这样的未审实现捷径。

**验收**：从已选外观提炼少量复用组件和样式即可；列出实际素材来源／许可或明确仅占位不可分发；用几条说明处理窄栏标题省略、动作换行、图库列数、浮层裁切和底部翻页。不安装新依赖，不自行改代码。
