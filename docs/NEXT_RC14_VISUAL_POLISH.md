## V1：DSH 顶部透出独立源窗口标题栏

用户截图可见源窗口的 `Probe...` 标题文字。当前 `qa/wallpaper-probe/Program.cs` 采集整窗口，JPEG Bounds 为 `X=0,Y=0,Width=w,Height=h`，没有客户端内容裁剪；前端覆盖时会把窗口装饰一并显示。透明度提高后，DSH 顶部无法遮住它。

**本轮优先采用用户提出的第二条路线：DSH 顶部不参与界面透明度调整，始终有可靠的不透明遮挡。**

- 只读确认真实 Windows 标题/菜单栏及会话顶部区域的 DOM 与背景规则，给这些区域设独立主题底色，不随 surface 改变。先保障实际截图所示顶部区域；不能用恢复整个 body 不透明来把整张壁纸遮没。
- 不以固定放大/向上平移整张壁纸作为主要修复：不同窗口比例/DPI 会改变遮挡关系，还会裁掉主体。测试普通、最大化、窄/高窗口和高透明度，确认源标题字与白条没有出现在 DSH 内容内。
- 若顶部遮挡在合法窗口尺寸仍不能稳定覆盖，再明确提出客户端内容矩形裁剪。它必须基于真实客户区/捕获坐标、DPI 和帧边界校验，不能固定砍 30/40px；JPEG 实际尺寸与 WHL1 header 尺寸要一致。交裁剪几何/协议检查与新原生资产后再做受监督短实测。
- 不改源窗口为 SW_HIDE/工具窗口、不重做已失败的完整隐藏调查、不改官方 EXE/app.asar。仅遮挡的方案不能写成“源帧已无标题栏”或“完全隐藏”。

## V2：聊天文字滚到输入区域后仍穿过去

用户已明确确认是聊天历史透过输入区域。两种状态使用同一个 `dsh-whale-mist` 外观插件（当前日常 rc.1、壁纸候选 rc.13）；激活背景时的附加透明规则造成了差异，不是另换了一套主题作者。

只读提取当前官方 app.asar 的实际 CSS，找到 `.Dc7zOa_composerSeat` 的底部遮挡渐变：由 transparent 过渡到 `var(--dsw-alias-bg-base)`。插件的 `backdropCss` 把该变量设成 transparent，于是整个遮挡渐变全透明。

隔离 DOM 对照 `visual-repro.json`：

- 普通状态：渐变 36px 处为 `rgb(8,11,20)`，能遮挡。
- 背景状态：36px 处为 `rgba(0,0,0,0)`，外围遮挡失效。
- 仅将底色临时恢复为实色的诊断对照：遮挡恢复。**这是定位对照，不是允许全局恢复不透明的修法。**
- 内层 `.RlGAzG_card` 的 `--dsw-specific-input-major` 背景仍不透明。因此已经验证的是外围/底部遮挡失效；若真实卡片实心中心还透字，必须另查 opacity、层叠与实际背景使用，不把该部分未经验证地归为同一根因。

修法要求：

- 在激活背景的主题范围内保护**完整 composer 区域**：卡片、外围遮挡、底部状态/控制区域都不能透出滚过来的历史文字；沿用主题实色做遮挡，或可靠裁剪聊天内容，保留壁纸其它区域。
- 保留滚动、选字、输入、卡片高度随内容增长、弹出菜单和多行编辑行为。不要只加一个不透明内卡片就宣布整个输入区修好，不盲目调整全局 z-index/overflow。
- 使用真实宿主样式/结构复现长消息滚动经过输入区；验证低/高 surface 下不漏字，停止后恢复；图/视频背景共享这些样式，也补受影响的回归。
- 哈希类名只是当前宿主线索，修改时优先稳定结构/标记与限定范围；不要编辑官方归档。新官方版本无法识别结构时，不应将整个应用盲目染成实色。

## V3：停止按钮落单且太小、不醒目

当前场景/模式字段和三个按钮都在一个可换行容器里。隔离真实设置 DOM：1280px 视口、560px 面板时，前两个按钮同排，停止独占下一排；三按钮均为 68×30px、12px 字，背景透明。先前的防文字零宽回归并没有验证按钮分组与显著性。

- 字段与操作按钮分成两组：场景/模式在上，开始/重新开始/停止在下方独立按钮组。
- 三个按钮统一高度、字号与可点击面积，例如高度至少 36px、14px 字；正常面板 400–720px 尽量同排且等宽，停止必须清楚可见。极窄容器采用明确、完整的布局，不能让停止成为不起眼的末行小标签。
- 使用明确的按钮背景/边框和主题前景色，与设置选项标签区分。保留 disabled、busy、清理失败可重试的所有语义，不因为视觉放大改变回调或启动条件。
- 保留 auto checkbox 16×16 和已有说明纵向布局；不要顺手改全局 `.wm-settings-option` 影响其它设置。
