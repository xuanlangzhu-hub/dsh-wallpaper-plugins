# 原生侧栏视觉与布局改版

2026-10-24。承接[用户UI要求](WALLPAPER_SETTINGS_SIDEBAR_REQUIREMENTS_20261021.md)及[rc.46验收汇总](RC46_NATIVE_SIDEBAR_ACCEPTANCE_SUMMARY_20261024.md)。这是经过当前源码与实机结果校准的实施方案，**本轮没有改实现或安装**。使用frontend-design技能作规划与自检，产品方向以用户要求为准。

## 方向：桌面端内的简洁调节台

Whale外观是陪伴聊天的右侧工具区。视觉重点放在当前对象和正在调整的控件；沿用DSH字体、主题、强调色和透明度，避免独立品牌大标题、额外装饰卡片或新配色。最右侧宿主页签继续承载内容，不覆盖聊天、不抢占其它页签或重做宿主右栏。

先区分“已有功能”和“完成设计”：rc.46证明了容器、图库、即时粒子和视频策略的部分真实链路；当前默认按钮、原始表单边框与长表单结构仍应改进。

## 已定位问题与最小修复接缝

| 证据 | 影响 | 修复方向 |
| --- | --- | --- |
| 原生按钮挂dsw-btn，但所查客户端／宿主CSS无对应规则 | 主次动作和默认表单外观混杂，不能靠类名假设已套官方视觉组件 | 建立只作用Whale的局部控件样式／组件小层，明示primary、secondary、quiet和danger变体；不临时导入未核实的SDK组件库 |
| bg-secondary、border-default在所查定义中缺失 | 预览底和图库边框回退不稳定 | 改用已定义的bg-layer／border-l2等语义token；维护局部token映射，不扩写全局别名 |
| EditorBody是padding16的连续内容，没有独立固定主控 | 长列表下停止／切换难到达 | 下一步核实宿主滚动约束后建立固定对象区＋独立内容滚动；不改整个body或其它页overflow |
| 无记录时所有作者checkbox显示indeterminate | 减号容易被理解为第三种值，真实未读与布尔值混在一个视觉状态 | 单独设计同步状态；保留真实值未知语义，不在纯样式步骤顺手改点击／下发逻辑 |
| 图库固定双列，当前详情标题单行且无小预览 | 窄栏长标题／选择与播放对象不容易辨别 | 分别覆盖360／520px；当前对象预览另步复用安全预览资源，不在第一步填假图或增加未接入占位 |

这些静态结论绑定冻结文件，并非已完成所有运行时样式诊断。第一步应补最小局部视觉层，避免一口气改命令、媒体和布局生命周期。

## 视觉约束

不新增独立色板。以下六组角色沿用现有Whale定义，色值仅说明当前Mist／Abyss参考，运行时必须跟随宿主主题及自定义色：

| 角色 | 已有token | Mist／Abyss参考 |
| --- | --- | --- |
| 正文底 | --dsw-alias-bg-primary | #f7fbff的现有半透明值／#0b111d |
| 局部控件底 | --dsw-alias-button-elevated-fill | 现有白色半透明值／现有深色半透明值 |
| 主文字 | --dsw-alias-label-primary | #153047／#e7ecf5 |
| 次文字 | --dsw-alias-label-secondary | #62798c／#a7b2c5 |
| 线条 | --dsw-alias-border-l2 | 现有浅／深色低对比边框值 |
| 强调／错误 | --dsw-alias-brand-primary、--dsw-alias-label-error | 强调默认#1468a8／#8c72f2并接受自定义；错误#b14754／#ff8795 |

用户自定义强调色（实测为#e8456e）不得被写死紫色覆盖。透明度复用现有控制器和主题投影，不叠一层新的固定不透明面板；需要保证亮背景下文字与焦点可辨，不能用整组opacity降低错误文字可读性。

字体一律inherit，保留用户已有中文字体；标题14–15px／600，控件与正文13–14px，次说明12px，数值等宽数字。根边距16px，分组间距20px，行内8px；控件可点击高度至少32px，开关视觉可小于点击区域。主按钮圆角约6px，图库沿用6–8px，不给每个字段套相同卡片。

焦点用强调色描边，hover与pressed使用现有交互底色；busy维持宽度并禁用重复提交，完成标记不推动文字。仅对响应用户操作的状态变化考虑短过渡，尊重减少动态；不加自动装饰动画。

## 默认结构

内容左对齐，数值右对齐；宿主控制宽度。建议的详情形态如下，当前对象小预览在其独立步骤完成后才出现：

```text
Whale 外观                      宿主页签
壁纸             界面
──────────────────────────────
Lucy                           更换
当前对象；预览按资源能力出现
开始 / 停止 / 检查清理          唯一主控
──────────────────────────────
作者设置                       按实际目标显示
粒子                      [开关]
光照                      [开关]
…内容区独立滚动…

画面
亮度                        81%
遮罩                        30%
更多画面选项                  收起
```

图库沿用单独视图：返回当前壁纸、搜索、分级、预览卡片。默认Everyone且隐藏未勾选分级的标题／预览；不增一个重复图库刷新按钮。普通本地图片／视频显示文件名和对应操作，不显示WE的日常模式／自动播放控件；播放策略跟随本地视频分组。

“界面”分区仅容纳主题／配色、不透明度、文字可读性、聊天底色与强调色。低频侧栏／画布深度、玻璃、预设管理等按需收起。当前不接全局reset、作者默认值恢复或新系统窗；没有能力的动作不放灰色占位按钮。

## 主操作与反馈

| 场景 | 主操作和反馈 |
| --- | --- |
| 未播放且目标可用 | 一个开始按钮；不因选中、打开侧栏或改参数自动开始 |
| 播放中 | 一个停止按钮；常驻对象区可达，不在每组参数重复 |
| 停止中／清理未知 | 对应忙碌或检查清理；不能假装未播放、让用户绕过门禁换目标 |
| 所选与播放对象不一致 | 明确显示当前播放对象和新选择；不能将新字段套给旧源或自动重启 |
| 参数修改 | 控件即时响应→忙碌→确认标记；不恢复保存草稿／应用三按钮链，不用每次成功Toast |
| 初始／发送结果未知 | 单独标明同步状态，可按需说明；不假称当前WE值已读取，不自动重放未知命令 |
| 确定失败 | 控件附近短错误和可执行恢复；详细错误按需，不把命令／协议堆到正文 |
| 更换／移除本地媒体 | 更换为次动作，移除收入明确的更多操作；不删除原文件，沿用已有存储租约与关闭证明 |

## 分步实施与验收

**第一步：只统一局部控件视觉。** 在单一来源ESM内增加Whale局部样式／小组件，修正缺失token引用；覆盖button、search、select、checkbox、range、summary的继承字体、主次／禁用／busy／focus状态。正文选择器限定data-whale-native-sidebar；外部顶栏触发器单独限定Whale标识，不能影响其它宿主按钮。维持DOM语义、data标识、控件顺序、现有事件和controller／Host接口；不改indeterminate行为，不新增图库请求、计时器、依赖或版本。

第一步修改ESM后仅用既有生成器同步client对应块，验证块外字节、业务状态和命令调用保持。只读CSS检查及有意义的组件／正式SDK回归覆盖样式边界、现有选择器可用、键盘焦点、卸载清理；沿用当前有界监督，不为几个样式机械重跑不相关原生矩阵。没有实际视觉就明确记未验收，不用CSS字符串断言代替视觉。

**第二步：重排首屏与滚动。** 按壁纸／界面分区和固定主控实施。先确认宿主滚动层，不覆盖host body；切分区、隐藏、关闭、重新挂载均不多发start／stop／作者命令，旧输入和文件选择票据正确撤销。单独覆盖360／520px、长标题、长参数组、None／图片／视频／WE状态及原文件页共存。

**第三步：当前对象卡与同步状态。** 复用既有预览资源及分级门禁；当前播放与所选目标必须分清，URL释放和迟到响应有据。再处理作者初始减号、原始标签、发送中和未知结果的视觉表达，不伪造值、不扩大到Lucy以外。

**第四步：小范围候选视觉检查。** 从固定底座独立整合，先离线和实际归档核验。未来按当时方便确认、新备份后再看明暗主题／自定义强调色、半透明／亮背景、窄栏／长列表和主控可达；默认恢复当轮日常。不能拿本次rc.46功能观察替代新UI视觉结果。

目前下一小步限第三步中的作者初始未知／发送反馈，先梳理真实状态及交互边界，再单独实施视觉表达。当前对象安全预览已离线闭合，新UI仍未实机验收。日常rc.42、官方宿主、Profile与媒体缓存保持；工作区manifest／生产assets仍rc.30。旧独立窗／模型请求／应用类／GPU／三体与推送清理不进入此任务。

## 对照原要求的自检

方案把个性放在壁纸和既有Whale主题里，工具区保持安静；没有加入新大标题、卡片堆叠、装饰配色或多层导航。“先全部换成官方组件”缺少已核实的组件API依据，因此改为已有语义token上的局部控件小层；“顺便重写整个表单”会扩大生命周期风险，因此第一步仅做视觉基础，布局单独推进。原生承载、即时应用、控件反馈和可读性均对应用户明确要求，未把容器接通当作整个改版完成。
