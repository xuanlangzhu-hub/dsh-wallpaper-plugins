## T1：时间基准混用，所有帧必然被配到最后一个 tick（P1）

`qa/scroll-painted-view.mjs:87` 的 tick.at 是页面 `performance.now()`；149 行 frame.at 是 Node `Date.now()`。195 行直接比较 `tick.at <= at + 60`，232 行传入 frame.at。在本次短运行中，epoch 毫秒远大于页面启动后的毫秒，因此循环走到最后一条；最后 scrollTop=0 就会把所有帧标成 0。

独立合成复现：ticks 为 `(100,0),(200,160),(300,320),(400,0)`，三个 epoch 到达时间全部映射到最后 `(400,0)`。这不依赖任何浏览器帧积压。它足以使“98 帧全 0，因此帧都旧了”的证据失效；未断言浏览器完全没有延迟。

修法：区分 frame 生成时间、到达时间和页内采样时间，明确单位和起点，保存原始值与转换。不要在未校准时配对，也不要用 +60ms 吞掉不确定性；无有效区间的样本标 unmatched。加人工序列检查，覆盖中间 tick、末尾回零、区间外和未来采样，不能全部落到最后。

官方 [Page 协议定义](https://raw.githubusercontent.com/ChromeDevTools/devtools-protocol/master/pdl/domains/Page.pdl) 将 `metadata.timestamp` 定义为 `Network.TimeSinceEpoch`；当前协议另有可选 `monotonicTimestamp`。报告把 timestamp 称为单调时钟是错误的。先检查本机浏览器实际返回哪些字段；epoch 秒转毫秒后可与 `performance.timeOrigin + performance.now()` 建立对应并测误差，不能把可选字段假定为本机已支持。到达时间只能量传输延迟，不能当交换帧时间。

夹具滚动的是内层 `[data-conversation-scroll]`，而 root 固定在页面视口。Page 的 scrollOffsetY 没有标识该内层元素；恒 0 不能证明内层没滚、画面旧了。可保留原字段，不用它推断内层 scrollTop。必要时在 QA 画面里放独立的状态/行编号标记以交叉核验，但标记与主线程 tick 同步也不自动证明合成器内层滚动的位置。

## T2：连拍与几何快照不足以“定案”（P1）

第一张有字、第二张无字，前后 JS 边界正确，只能说明所读状态与两个异步取图不一致。没有同一帧的边界/画面归属，就不能唯一归因于截图返回旧帧，也不能排除用户报告的瞬时呈现。

撤回报告中的排他性解释，保留原图/数据，写为“原因未区分”。22 次抽样无泄漏可作为有限结果，不能当自然滚动零泄漏的证明。不要按“早于最近一次滚动”全删帧：连续滚动期间正常到达的帧也可能早于最新输入；原始帧应保留，用其生成时间、滚动事件区间与配对误差单独分类。

全局延迟 RAF 同时改变主题与探针，且主题在延迟回调执行时重新读几何，所以它不自动等于“把旧裁剪值晚写一帧”。负对照应只作用于目标裁剪写入：记录计算值/计算时间/真正写入时间，正常版与延迟版共享同一测量器。先证明对照在滚动期间确实产生可见错位，再使用其阳性结果校验检测能力。

## T3：输出保护仍可经 junction 绕过（P2）

`qa/temp-profile.mjs:141` 使用 `resolve(path)`，只是语法路径解析；owned 保存的却是 realpath。位于证据目录内的 junction 指向本轮 profile 时，输出路径看起来在 profile 外，实际文件写进了 profile。

安全合成复现：仅用本脚本创建并登记的 profile，创建精确 junction，`evidencePath` 接受路径，`verifyPersisted` 成功；先 unlink 本次 junction，再调用正常 `removeProfile`，报告实际文件随 profile 消失。没有浏览器、历史目录或用户数据参与。直接 profile 内输出的拒绝已通过。

修法：对目标文件/未创建目录向上寻找最近存在祖先，realpath 后补回尚不存在的后缀，再按 Windows 路径规则比较；处理 junction/链接以及大小写一致性。实际写入位置与检查位置要一致，写入/持久化核验时重新核验。合成回归同时覆盖直路径、目录链接、新文件后缀和外部正常输出；只清理本轮精确登记对象。
