## R1 [P1] 常驻参数必定被原生程序拒绝

位置：`dsh-whale-mist/qa/wallpaper-probe/Program.cs:115–123`。
Host 按生产路径传 `[HWND, output, --forever, 30, pipe, --owned-location, name]`。
原生先移除 owned-location 组，再把 --forever 从数组删除，却继续按旧位置读取 fps，
并要求 args[2] 仍等于 --forever。删除后的 fps 位置是 pipe，校验立即报 Usage。

对包内 EXE 做安全的占位 HWND=0 对照：

- 日常同形参数退出码 1，ArgumentException / Usage，尚未进入窗口身份校验。
- 预览同形参数通过参数校验，随后因占位 HWND 0 无效而拒绝。

这是参数解析对照，没有实际采集，不把预览对照称为真机播放通过。
真实日常会话会在创建源窗口后遇到同一拒绝，无法得到首帧。
当前 probe-cli 测试只断言非法请求拒绝；Host 测试用替身子进程，因此两边都没有锁住有效生产参数。

要求：修正位置参数解析，保留日常与有限预览语义、父停止通道和资源归属。
增加调用真实 helper 的有效参数解析回归，至少证明 Host 实际生成的日常参数能越过 Usage 校验；
可抽取纯参数解析或使用不会创建窗口的验证入口，但不能复制另一份假解析器来证明正确。
同时保留非法模式 / 时长 / fps / 参数混用拒绝，重建并同步包内 DLL / EXE。

## R2 [P1] 自动播放会读取本轮新勾选，并在手动停止后被迟到回复重新启动

位置：`dsh-whale-mist/src/client.js:2523–2536`。
effect 读取的是持续变化的 settings.weAutoStart，没有冻结启动时的选择。
await loadHostStatus 后只查来源与主题，未绑定用户操作代号，也没确认期间是否已手动播放或停止。

真实设置控件回调的隔离复现：

| 操作 | 应有结果 | 实际结果 |
| --- | --- | --- |
| 启动时 auto=false，立即勾选「只保存下一次启动」 | 本轮启动数 0 | 启动数 1 |
| 启动自动状态查询被延迟，用户通过可用按钮手动开始再停止，再放行状态回复 | 保持已停止，启动数维持 1 | 启动数变 2，状态 playing |

开始与停止按钮在复现时 disabled=false，没有绕过不可点击状态。
这会违背界面文案，也会让用户刚关闭的源窗口再次出现。

要求：冻结本次启动的自动播放资格；等待 Host 的自动操作绑定明确代号 / 用户意图。
手动开始或停止、离开日常模式、来源切换、恢复默认和卸载后，旧自动请求不得生效。
补勾选早于 300ms / 5s 定时器、状态回复迟到期间真实手动开始→停止、来源离开再返回等回归。
保留后续完整启动按已保存选择自动开始的功能。

## R3 [P2] Host 未就绪的第一次查询耗掉唯一尝试，5 秒兜底无效

位置：`dsh-whale-mist/src/client.js:2530–2543`。
attempted 在查询 Host 前就被设成 true。首查失败或不可用后不复位，5 秒定时器会直接返回。

状态查询数仍为 2（初始化与首次自动检查），启动数 0。
要求的「Host 稍晚就绪可有界等待」没有实现。

要求：区分正在检查、尚未就绪和已经实际尝试启动；就绪检查有截止时间与有限重试，
服务恢复后仅启动一次。确认 HTTP 成功及有效 available 字段，不能把错误 JSON 当就绪。
不要把查询重试做成无限建窗，手动停止 / 来源变化的取消优先于后续重试。
