# 原生侧栏：普通本地视频入口

2026-10-23，接续[缩略图资源补修](WALLPAPER_NATIVE_PREVIEW_RESOURCE_REPAIR_20261023.md)。本轮接通普通本地视频的选择、更换、移除、使用已存视频；复用本地图片的安全交接和有界事务。开发源码与隔离SDK范围通过，**未构建候选、安装或操作日常DSH／WE，未作主观视觉验收**。日常DSH0.2.1-rc.2／外观rc.42／Git Bash0.1.1保持；manifest／生产assets仍rc.30。

## 本轮行为

- 无背景时显示“本地视频／选择视频”；已有缓存才显示文件名、更换、移除，关闭来源但缓存仍在时才显示“使用已存视频”。原生宿主按钮、字体、颜色和布局规则沿用图片入口，没有新建独立窗。
- 选择后验证并生效，无保存／应用按钮链；处理期间busy且禁止重复操作，错误局部短句反馈。视频来源生效后收起WE主控及WE播放选项，避免把普通本地文件混称为WE图库video。
- 接受非空、1GiB以内的`video/mp4`或`video/webm`，还须真实浏览器`loadeddata`验证；扩展名和MIME本身不能证明可播放。图片原64MiB及格式规则保持。
- 普通视频仍走既有浏览器背景层：静音、循环、内联播放；现有失焦／页面隐藏／减少动态策略保持，本轮没有新增motion控件。用户需先明确移除本地图片或关闭WE背景，才能换到本地视频，不暗停其它来源。
- 取消选择不发Host请求、不写Blob；文件选择器打开时保存票据，收起侧栏、切换会话／主题或设置改变后，迟到文件不能写入新上下文。

## 共享安全链

`client.js`把图片的有界记录操作、控制器交接参数化为image／video；`editBackgroundImage`入口保留，新增`editBackgroundVideo`。两者使用同一媒体写入租约和来源操作通道，分别写既有IndexedDB `backgrounds`的image／video键，不更改数据库版本、Profile或文件原件。图片和视频不能并发写缓存；旧媒体入口也尊重同一写入租约。

修改前读取实际Host关闭状态并消费同轮关闭证明，要求无活动来源、无未决命令；没有activate、start、stop或循环轮询。解码、读取、写入共用六秒总截止与上下文检查。视图离开或到期中止解码／事务，清理临时元素和URL；写事务若尚未收到终结事件，即使界面已收到失败，物理写入租约仍保留，迟到完成只能释放自己的租约，不能提交来源。

导入先校验视频，再写对应Blob，最后严格保存background来源；来源保存失败保留缓存供显式“使用已存视频”恢复。移除当前视频先确认保存none，随后删视频记录；来源保存未确认时保留原文件，删除失败则如实报告当前已为none且缓存尚在。新配置确实从未有外观记录时允许首次创建；原记录丢失／损坏、存储漂移及重入新选择仍拒绝覆盖。

`createMedia`、主背景load／reconcile及作者生成块与开工版本逐字一致。此前Preview归属修复逐字保持。旧通用设置的媒体入口并未全部迁移到有界新API，不扩称旧入口的所有IO已经改造。

## 本轮失败与修正保留

- 初次新视频QA复制了图片用例的`one.png`期望及`expireVideo`不存在方法，产生6项夹具错误；改为实际视频文件名与共用六秒期限后通过。所有原始失败日志保留。
- SDK脚本从旧组迁移时遗留自引用脚本路径，启动前ENOENT；修正引用后图片11项通过。另一次新解码诊断脚本有括号语法错误，启动前即退出；语法修正后继续。两次均未启动浏览器。
- 最初canvas captureStream／MediaRecorder在该隔离输入生成的WebM只有110字节，无视频帧；插件拒绝且未保存来源。独立浏览器解码同样报告DEMUXER_ERROR_COULD_NOT_OPEN；附加画布并requestFrame仍为空，原失败保留，未延长期限或改错误白名单。最终改用有界WebCodecs生成6个VP8帧并最小WebM封装，先独立解码验证后再测试产品入口，完整13项通过。
- 首轮合并组检测到作者生成块不一致，原因是本轮编辑工具把原块的122个CRLF规范化了；恢复开工原块的准确字节，断言换行归一化后的运行文本完全相同，再补生成／语法／CSS检查通过。此前SDK输入与恢复后客户端只差这段等价换行，未为纯格式变化重复全部SDK。
- 中间视频SDK使用过无匹配项的模式选择器；最终改成产品真实`data-whale-playback-option=weMode`，重新运行13项确认视频来源确实隐藏WE控件，未保留空断言作为验收证据。
