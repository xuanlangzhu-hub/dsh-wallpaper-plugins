| 操作 | 行为 |
| --- | --- |
| 拖动 | 只更新显示值，不保存草稿或下发命令 |
| 正常松手，包括移出控件后松手 | 只提交最终值；回到起始值则不提交 |
| 方向键/Home/End/Page按键及连续重复 | 按键结束时提交；键盘调节后焦点移走也只完成一次 |
| Esc、pointercancel、丢失捕获通知、窗口失焦 | 丢弃本次未完成调整，不下发回退命令 |
| 收起/关闭所在视图、切目标或代次、卸载 | 使本地编辑票据失效，迟到的完成事件不能提交 |
| 上一条应用仍在执行 | 已完成的新调整只保留各字段最新值，上一批确认后串行发送 |

滑块起始数值仍来自作者默认值或插件记录，**没有读取WE当前值**。勾号只表示下发确认，不证明实际画面符合预期；已发送的修改不会因取消后一次拖动而自动撤回。布尔开关及上一轮的明确重查/清除记录路径保留。

## 实现与约束

- 复用`author-properties-contract.js`的`validateAuthorValue`。作者面板生成器只额外导出已有验证函数，根接入将该函数传给原生协调器，不复制一套数值校验，不改变Host协议或执行器。
- 支持有限范围的整数和小数，遵守原有min/max、fraction、step及安全key约束。无step整数使用整数界限/步长1，小数使用any；显式步长仍由协议校验。整数声明却含小数起点/小数步长的特殊格点暂不呈现，避免擅自舍入成另一个值。
- 独立的本地预览Map覆盖显示；它与待提交Map分离。旧批次回包不能覆盖正在拖动的预览。每字段只有一个本地编辑所有者，票据绑定context、epoch和具体可见视图，另一个视图不能抢走同字段的拖动。
- 完成时才把值交给原有draft/apply串行通道。只传本次变动字段，保留revision/fingerprint/目标身份、最多4批、整段12秒、读取/清除4秒及物理请求未结算不解锁规则。失败/未知不自动重试，schema stale仍拒绝。
- 未开始有效指针/键盘交互的孤立input事件不会提交；不把迟到input当作新操作。当前离线验收覆盖鼠标和键盘，未验证所有辅助技术的直接调值方式。
- 初始读取入口仍显式触发；其它作者字段、独立窗互斥和整体视觉尚未完成，不能称为全部作者设置验收。

## 中途失败与修正

早期SDK报告全部保留，不能描述为一次全绿：

1. 首次把range中点预期为2，浏览器实际按整数格点把2.5取为3；改为明确的40%位置后验证2。
2. 第二/三轮以`releasePointerCapture`测试外层range丢失捕获，但原生range由浏览器内部处理捕获，该操作没有证明测试需要的通知。临时在pointerup要求外层`hasPointerCapture`又阻断正常松手，第四轮失败后撤回。最终保留正常松手，丢失捕获按DOM通知分支验证，并明确范围。不能把上述测试假设写成已定位的生产捕获bug；中途对此的过早判断已更正。
3. 第五轮用Playwright鼠标点击切目标，而此前鼠标仍按住，工具先松手，导致测试实际上完成并提交了拖动。改为在仍按住时调用实际DOM点击处理器，切换完成后才释放鼠标，验证零提交。没有通过修改产品行为掩盖该夹具问题。
4. 第六轮55流程通过后，补入控件外松手和多次键盘完成合并两项，最终57流程通过。所有7次Node父进程均确认退出，最长一轮23.05秒，未触发45秒SDK父监督。第三轮另有`owned Edge close deadline`，当时浏览器退出未获确认，原报告保持失败；收尾以真实只读CIM核验其专属PID47032及直接子进程均不存在，证据为`third-browser-late-check.json`。这是稍后的根/直接子进程缺席证明，不倒称当时已确认完整进程树退出。没有盲删其profile/证据或全局终止浏览器；其它6轮含最终轮均即时确认自有浏览器退出。

原生拖动取消后的迟到input会恢复控件显示而不提交；第二指针不能抢占同一交互。上述实现包含在最终源码和57流程输入指纹中。
