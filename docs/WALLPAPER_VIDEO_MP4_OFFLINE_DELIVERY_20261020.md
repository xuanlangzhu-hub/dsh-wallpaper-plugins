## 结论与范围

用户在 rc.38 日常交接后选择先扩壁纸类型，顺序为视频、网页、应用可行性，作者公开参数后排。本轮已完成 **已登记、本地 MP4 视频的手动实验播放源码接入**，并将核对过的 13 个源码/QA 文件从隔离副本提升到开发目录。**未安装、未制作新候选、未验证实际视频画面或音频**；日常仍是 DSH 0.2.1-rc.2 / 外观 rc.38 / Git Bash 0.1.1。不能向用户声称当前安装已经能播放 WE 视频或所有壁纸。

官方 [命令行接口文档](https://help.wallpaperengine.io/en/functionality/cli.html) 允许 `openWallpaper -file` 指定 project.json 或直接媒体文件（例如 MP4），并用 `-playInWindow` 创建命名窗口。本轮沿用既有受控源窗口、采集和清理链路；官方接口说明本身不证明本插件的视频捕获效果。

## 实现与限制

- 登记：仅 `type: video` 且本项目内的非空 `.mp4`（大小写均可）成为手动实验可用条目。web、application/unknown、其它视频容器仍拒绝；`available` 仅表示符合登记条件，不证明容器/编码可解码。
- 启动：请求只提供 ID，Host 从自己的目录快照重新核验根目录、项目声明、类型及媒体路径，向 `--we-open` 传重新核验后的 MP4，而不是视频的 project.json。请求体伪造 project/type 等额外字段无效；公开列表不泄露路径。
- 拒绝：缺失、空文件、改名/改类型、越界声明、链接及非批准根不能启动。scene.pkg 后备严格限于 scene，不能替视频兜底。
- 界面：通用设置文案、主端权威执行器、吸附面板和独立窗的类型谓词同步接受受限 video；保留清理锁、并发/当前目标约束及年龄过滤。自动播放验证名单保持 Lucy，新视频仍标实验。
- 原生：JS 与 C# 的受控文件参数允许绝对 JSON / MP4，继续拒绝不支持后缀、控制字符、设备路径、ADS 等。本轮加 `--validate-wallpaper-file` 纯校验入口，位于任何桌面切换、窗口枚举/启动之前。
- 会话/采集/停止实现没有改动；复用既有路径。音频、作者参数、特殊编码/DRM、播放循环/暂停恢复及长期效果均未验收。
