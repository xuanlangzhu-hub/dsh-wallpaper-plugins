## 界面和行为

本地图片入口只在“无背景／图片”来源下出现，沿用宿主按钮、字体和主题变量，没有新增固定配色或大块诊断说明。未保存图片时只显示“选择图片”；有图片后显示文件名和更换／移除，来源关闭但仍有缓存时才显示“使用已存图片”。图片生效后收起WE播放主控和播放选项，避免把图片与WE图库中的video／scene混称。

WE来源下保留既有“关闭背景”。用户明确关闭完成后才能导入图片；新图片API拒绝wallpaper／video来源及外部活动Host，不暗中停止当前来源，也不自动开始任何壁纸。普通本地视频另一步迁移。

选文件不需要保存／应用按钮。操作期间有busy及禁用反馈；取消选择不发请求、不写存储。打开选择器时记录当前票据，侧栏收起再展开、会话／主题往返、设置变化都会撤销旧票据；晚到的文件不能应用到新的上下文。

错误局部显示短句。图片已缓存而背景来源未保存时，保留缓存，提供明确“使用已存图片”重试；不再次上传Blob。移除失败与保存失败分别反馈，不用“保存失败”解释删除错误。

## 存储与安全交接

- 复用原IndexedDB `dsh-whale-mist.media`／`backgrounds`／`image`，不另建媒体库，不改video记录。文件仍保存在浏览器本地，未保存绝对路径。
- 新入口接受非空、最大64MiB的PNG／JPEG／WebP／GIF／BMP／AVIF类型，先用实际图片解码验证再替换；损坏图片不覆盖原图。真实浏览器本轮覆盖PNG，其余格式未逐项实机验收；SVG不在本轮入口范围。
- 新controller入口为 `editBackgroundImage(action,file,options)`。来源只允许none／image；新背景保存继续复用严格单字段 `saveBackgroundSource`，保留其它外观和扩展字段。替换已激活图片无需重写来源，但仍核对实际外观存储，不能隐瞒外部偏好漂移。
- 全新配置允许首次保存，但仅限apply启动读取明确确认该key不存在、偏好对象一直未被替换的情况。损坏、不可读、启动时存在但后来丢失的记录均不冒充新配置；本轮也补上同一严格保存路径的WE首次启用反例。
- 来源交接先读取当前Host静止证明，再准备或检查同一关闭栅栏并同步消费proof，保持封闭。不activate或普通start／stop。冷none入口仅在已确认Host静止时准备栅栏；外部活动、pending、写未知或证明无效均拒绝。
- 图片解码、数据库打开／事务共享最长6秒的总窗口；取消和期限传至具体IO。数据库写在真实transaction完成后才确认。超时的写事务请求abort，但writer租约保留到终结事件；迟到事件只能释放本轮租约，不能继续提交来源。
- 本controller内，新图片与旧store／remove共用writer互斥，拒绝并发操作，不排队轮询。旧接口的默认解码等待及原有数据库路径仍保留，不宣称全部旧媒体IO已迁成有界接口。
- 移除当前图片先严格保存none，再删除图片记录。来源保存未知时不删文件；来源关闭已确认但删除失败时保留文件，返回实际none及已完成的来源变化，供用户明确再次移除。
- 保存／删除部分完成、取消、投影或存储故障均保留可观察结果，不用旧数据回滚覆盖新选择。这不是IndexedDB与localStorage的跨库原子提交，也不提供跨独立renderer的分布式CAS；两步失败通过保留文件和明确重试恢复。
