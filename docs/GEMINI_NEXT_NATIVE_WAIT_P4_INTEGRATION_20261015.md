先读[隔离结果](NATIVE_WAIT_P4_ISOLATED_RESULT_20261015.md)和[三体P3实测](COMPLEX_SCENE_P3_FOREGROUND_RESULT_20261015.md)。本机已确认请求18ms实际约31ms，异步高精度原型约18.4–19ms；20项原型检查通过。**本任务只接入该等待方案，不重写P3观测，不处理壁纸鼠标联动停顿。**

## 改动范围

- qa/wallpaper-probe/ 中新增一个生产可用的局部等待组件，参考 qa/perf/native-wait-probe/AsyncTimerDelay.cs 和 KernelWaitTimer.cs。
- Program.cs仅在实际capture作用域内创建并释放该实例；仅将普通ExecutePacingWaitAsync的delay委托换为可取消的异步等待。工具型CLI/任务栏worker不能无故创建计时线程。
- 目标仍30fps，保留当前即时预算、整数截断、最低1ms和测量边界。ExecuteEmptyRetryWaitAsync的2ms/Task.Delay策略保持，不把这次修改扩成高频空帧轮询。
- P3的22字段/含义、Fake时钟与delay委托、回退日志兼容及P2/前端/Host均保持；不得改RAF、JPEG/尺寸、设备、源位置、主题、任务栏或自动播放名单。
- QA项目应链接实际新组件并跑实际编译方法，避免继续维护一份“测得好”的复制实现。现有隔离对照可保留普通/直接等待作为控制，不重复造工具。

版本保持工作区rc.30，生产assets和三个tgz均不动；独立构建输出放本仓库.tmp新目录。日常安装为rc.28，不安装、不操作DSH或WE、不改Profile/Local Storage/系统设置、不提交/推送。

## 必须守住的行为

1. 每capture实例最多一个计时器/后台等待线程及一个待处理请求。异步恢复不能在计时线程上执行capture代码；不能每帧创建线程/Task.Run、链接CTS/事件或忙等，不调线程优先级/全局计时器。
2. 父停止/EOF使用现有stopSignal取消当前等待。实例退出时唤醒空闲或在途等待、结清已接收任务，确认线程退出再关句柄；不能让调用方永久等待，也不能关闭正在等待的句柄。
3. 创建高精度计时器不支持/失败时，明确选择当前Task.Delay后端并记录一次原因；不改全局配置来绕过。回退仍尊重取消，不能报告自己使用高精度后端。
4. Set/wait/cancel等运行期错误不得吞掉或虚报清理成功。明确报告、停止并释放，或者证明一个安全且有界的回退；并发/取消/关闭竞态不得污染下一轮。不要靠改大Host超时蒙混过关。
5. 后端信息只需一次启动诊断，避免每帧日志。保留现有P3请求/实际等待统计真实测量异步桥接后的耗时。

QA原型有意没有完成上述创建回退/运行故障与真实helper接缝；不要直接改名复制后宣称生产完成。
