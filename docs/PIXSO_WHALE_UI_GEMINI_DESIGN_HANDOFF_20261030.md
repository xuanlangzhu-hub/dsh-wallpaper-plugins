## 2. 设计方向和现有交互

**自然、简约，像DSH自带的最右侧工具栏。** 保留宿主聊天空间和整体风格；用克制的强调色、明确层级、整齐间距和统一控件，考虑主题底色／透明度与壁纸背景下的可读性。

首屏突出当前操作对象和常用动作，低频设置有清楚的具名入口。播放用“▶ 播放”等图标加文字，停止保持清晰；纯图标入口应有可理解提示。控件本体与展开层一起设计：下拉、分段选择、开关、滑块、颜色、输入框、菜单都要有一致状态。

这些交互已有成果，设计须保留：

- 图库点卡片只选择并留在图库，明确区分“选中”和“正在播放”。点播放才开始／显式切换目标，不能暗示点选已切换成功。
- 图库上方叫“壁纸参数”，进入详情；详情的“更换”返回图库。
- 作者参数支持不止Lucy；支持范围与当前能力标识保持真实。控件修改即时提交，不恢复“保存草稿／刷新草稿／应用”三按钮常规流程。
- 参数处理、下发确认、失败、未知／待确认必须可区分。成功反馈轻量就近，必要错误短而可操作；刷新／重试尽量直接。不能用设计稿上的勾号承诺画面已生效，未知结果也不能伪装成成功。
- 保留全年龄／敏感／成人的独立选择，默认仅全年龄；稿件使用安全占位素材，不读取或展示用户未允许的敏感壁纸。

长时间使用后参数偶发失败的根因仍未知；本轮只设计状态表达和恢复入口，不宣称修复了该问题，也不改状态机或生命周期。

## 3. 首轮交付范围

在目标文件内新建清楚命名的设计区域，先完成**一套主方案**：

1. 壁纸参数页：当前壁纸／播放条、常用画面调整、作者参数和轻量状态。
2. 图库页：搜索、分级、缩略图、选中／播放区分、分页和切换操作。
3. 界面设置页：主题／配色、透明度与文字可读性，低频设置收拢。
4. 小型控件状态板：按钮、开关、滑块、下拉／菜单，以及处理中、确认、失败、禁用和未知状态。别把诊断说明放进用户主界面。

建议默认用1440×900宿主示意、约400px右侧栏展示上下文。先做常规宽度；窄至280px、宽至520px的处理写成适配说明即可。深色先完成，补一个浅色关键状态；不必一开始铺满所有主题和尺寸。若要比较，只额外做一个顶部操作区备选。

可自行寻找公开图标和组件参考，优先统一风格、可复用资源；记录实际来源和许可。私有资源库按账号权限读取，需付费资源先列出来。当前Pixso组件库为空并不意味着需要手画所有图标。设计资源与未来代码组件库分别评估，本轮不安装前端依赖。

已明确的信息直接沿用；只有缺少会改变主流程／页面范围的关键事实才集中问一次。一般视觉细节用合理默认，不反复确认已有偏好。
