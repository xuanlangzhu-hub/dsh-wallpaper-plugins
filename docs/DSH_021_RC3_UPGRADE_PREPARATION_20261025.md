## 执行顺序与失败恢复

`run-step.cjs` 逐项监督 `transaction.py`，所有实际阶段先验证本轮授权、固定输入与关闭状态；不允许直接越过预检调用安装器。

1. `preflight`：确认当前无 DSH／采集／独立窗／安装器等阻塞进程，锁定原 WE 的 PID、精确创建身份及程序路径；核验日常宿主和插件、新旧安装器签名、8项来源、281项工作区保护输入与磁盘余量。
2. `backup`：关闭状态下创建本轮新备份，核验全部字节及链接清单；未完成不能安装。
3. `plugins`：仅通过已核验的日常 CLI 执行 `plugin --profile desktop add <固定tgz>`，安装 Whale rc.47、Git Bash0.1.2。仅该子进程设置本轮 `DSH_HOME`，不改系统环境。分别核对实际文件与 tgz；桌宠、推理档位及其它设置保持。
4. `host`：安装已签名官方 rc.3 到现有 `C:\Users\HP\AppData\Local\Programs\DeepSeek Harness`，随后核验 EXE／app.asar／CLI 精确哈希及原 WE 身份。
5. `verify`：重开前验证两项目标插件、两项保留插件、宿主及数据差异范围。通过后再请用户正常重开，先确认布局／外观和播放停止，再安排必要短验；离线通过不替代这些验收。Git Bash真实命令不在本阶段自动执行。

官方安装器采用原生 CreateProcess 参数字符串，固定绝对目标，`/S` 静默且 `/D=...` 必须最后、不加引号；该要求见 [NSIS 官方安装器参数说明](https://nsis.sourceforge.io/Docs/Chapter3.html#installerusage)。不通过 shell 拼接执行。

各阶段父监督上限：预检90秒、备份360秒、插件150秒、宿主180秒、关闭核验150秒、失败现场保留360秒、旧宿主恢复180秒、数据恢复360秒；内部安装器子进程另有120秒上限。每个启动／结束回执落盘，并保存原生进程创建时间。超时只收束本轮自己启动的子进程树，不终止日常 DSH 或原 WE。**不能确认子进程退出时阻止后续写入，不盲目重跑或放宽超时。**同阶段日志排他创建，避免重复启动留下孤儿。

关闭状态下若升级失败且本轮子进程均确认退出，依次 `retain → rollback-host → rollback-data`：先完整保存并核验升级后的用户数据，再恢复签名旧宿主；原目录通过同卷 rename 隔离，最后恢复本轮备份。失败现场、新增文件和历史 backups 都保留，不递归删除。损坏备份或不完整保留证明必须拒绝恢复。

用户一旦重开并交接，旧授权标记结束，不能随后用旧备份直接覆盖新增数据；需要另行安排当时关闭状态与新数据保护。安装器若意外启动应用，关闭守卫应停止后续步骤，不能强杀绕过。
