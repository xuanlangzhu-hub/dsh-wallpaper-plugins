CPU 是占本机 **32 逻辑处理器总容量**的比例，按每 PID 原始 delta/time 复算并与采样器汇总核对；
不是单核百分比。工作集是有效观察均值，不等于独占物理内存。
绘制速率用各自客户端状态差值/时钟窗口计算，覆盖约 72–84 秒，含采样外围取证，
与 CPU 的有效区间不是精确同步帧。延迟用客户端累计平均×帧数的增量重算，表示其 capturedAt→绘制报告，
不等于从 WE 原始渲染开始的完整端到端延迟。

**观察支持保持用户当前独显路线，不需要为了这张场景把采集默认改到核显。**

核显的报告延迟约低 4ms，未形成可见帧率优势。两次重复不足以证明普遍性能优劣、功耗或游戏影响；
不按相对 CPU 百分比计算一个“优化倍数”，也没有立即修改生产默认策略或加入选卡 UI。

## GPU 的正确口径

按 PID+LUID+引擎，从每次原始 processGpu 的实例最大值取观察均值，保留计数/峰值/实例集。
没有使用旧摘要中混合不同 LUID 的 engineMaxByType 给某张卡下结论。

- NVIDIA 采集 helper 自己的 NVIDIA 3D 引擎观察均值约 0.76–0.77。
- Intel 采集 helper 自己的 Intel 3D 引擎观察均值约 1.67–1.68。
- 共享 WE 进程的 NVIDIA 3D 引擎均值四段约 78.18/80.55/80.55/78.08，
  源和原桌面同 PID；改采集卡没有把 WE 的独显渲染转到核显。

这些是各进程在具体引擎上的计数，**不能把不同显卡的百分比直接比较为运算量，也不是整卡占用/瓦数**。
WE 数据包含原桌面与新建场景，不能把整个 78–81 当插件新增。本轮没有无壁纸基线或功耗/时钟数据。
完整 per-process CPU、RAM、按 LUID 分开的四项 GPU 内存与 GPU 引擎值保留在 summary JSON；
进程树 CPU 均值之和仅作指示（各 PID 时间区间略不同），不冒充精确共同窗口总量/净新增成本。
