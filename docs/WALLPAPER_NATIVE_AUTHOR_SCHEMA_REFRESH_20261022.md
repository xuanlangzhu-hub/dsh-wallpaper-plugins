## 用户行为

作者设置区保留一个“刷新设置”入口，读取成功后也能手动刷新，不做后台轮询。有本地编辑票据时改名“取消编辑并刷新”：鼠标按下不先让输入框失焦，点击后同步取消本地编辑，再读取，避免刷新动作顺便提交旧文本或数值。滑块、文本、数值与输入法候选的旧票据均失效，迟到松手、blur、Enter不能恢复旧提交。

正常Tab移走焦点仍按原有普通失焦规则完成输入；该行为没有改成全局取消。刷新在作者执行通道空闲时才可开始；正在执行应用时拒绝新读取，不抢走执行中的操作或较新的本地输入。

| 读取结果 | 行为 |
| --- | --- |
| 参数结构未变 | 显式重读插件记录，替换不可变字段描述符；不重发参数 |
| 结构已变，旧记录干净且有明确终结证明 | 验证新结构及默认值后，通过有revision比较的本地刷新建立新记录 |
| 字段移除、类型/范围变化、变为空结构 | 刷新成功后重建控件，旧描述符/节点不能继续提交 |
| 旧记录未发送、发送中、结果未知或证明缺失 | 保留Host旧记录，禁用即时编辑，显示结构变化及暂不能自动刷新 |
| 读取与刷新之间又变结构、版本冲突、回包损坏或目标变化 | 拒绝本次结果；不重试、迁移、重放或自动恢复默认壁纸参数 |

刷新后的数值是新作者默认值/插件记录，**没有读取WE当前值**。旧记录即使曾确认下发，也不代表新参数结构中的实际值已知。结构刷新不撤回此前已发送的效果。

## Host与客户端约束

新增既有`POST /api/author-properties/draft`的`action: refresh-schema`，沿用认证owner/选择/分级/生命周期、schemaFingerprint与expectedRevision。仅当当前元数据结构与旧记录指纹不同、旧dirty为空、delivery为none或confirmed、执行器与Host应用通道均空闲、目标仍有效时允许。拒绝values、discardKeys和acknowledgeUnknown搭车；操作只替换插件记录，revision加一，建立新默认值、dirty为空、delivery=none，并返回refreshed/mutation/currentValuesKnown=false的明确证明。

这里不是reset：不产生待发送默认值、不生成执行计划、不调用WE，也不迁移旧同名字段的值。已有记录的schema GET继续只读，不因读取自动改版本。重复提交、其它编辑者抢先、再次变结构都由原比较与身份门禁拒绝。旧Host不支持新action时客户端失败保留，不回退为reset或apply。

客户端仅在用户显式读取、严格stale=true/values=null/dirtyKeys=[]、同revision的none/confirmed证明及明确非busy/有效目标下请求此操作；请求前用原`validateAuthorValue`验证新字段与默认值。确认回包还需核对指纹、revision+1、默认值投影、无dirty、delivery=none及明确非busy；证明不全仍禁用编辑。共享校验器、执行器、其它恢复动作及原事务期限不改。
