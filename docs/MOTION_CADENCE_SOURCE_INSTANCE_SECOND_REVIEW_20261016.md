## 进入脚本准备时完成的检查项

这些是将方案变成可执行工具的准备任务，不是要求再让小G循环修调查文档，也不是实机授权：

1. **隔离脚本、默认预演**：只放新`.tmp`证据目录；先给出目标/布局及全部身份/状态检查结果。实际移动必须显式进入本轮操作模式，不修改插件或运行资产。现有C#验证方法在报告中是身份要求的描述；脚本要落实可调用入口或等效严格验证，不能假定从PowerShell已能直接调用内部方法。
2. **绑定与时序**：只从当前Host会话读取location/HWND/PID，记录进程启动身份及capture绑定；执行前再次核对唯一标题、句柄、进程身份、非最小化/非cloaked。等待`native.tucked`及所需worker状态真实成立，设置有界deadline；不把固定约1秒sleep当就绪证明，不与任务栏worker动作并发修改窗口。任何条件不明时拒绝移动，不另开第二个源给DSH接入。
3. **坐标与结果**：按当前工作区/显示器和DPI坐标体系计算可见布局，不把示例x=1280直接当通用坐标。记录移动前外框/客户区、style/exStyle、capture尺寸；检查SetWindowPos返回值并读回实际位置/尺寸/样式和新帧状态。若无法在不缩放源、不遮挡关键画面条件下并排，不自动resize或换屏，记录布局不可用并另定方案。NOSIZE是请求标志，不是省略结果核查的理由。
4. **运行条件**：使用确认过的本轮安装与启动环境；诊断trace关闭，品质/FPS/物理参数保持。报告采用offscreenStart=false会走capture-then-tuck，与rc.32初始屏外路径不完全相同；窗口化边框/尺寸及屏内条件都需记录，不称严格历史A/B。DSH/源保持普通窗口，鼠标/前台约定清楚，不触发已有全局pause规则。
5. **停止恢复**：正常用户stop后，核对本轮capture/worker退出、源不存在、Host关闭结果及原WE身份保持；遇worker未结清仍按现有门禁报告未知/保留，不绕过。若临时启动环境或安装发生变化，按当轮新备份恢复，不套用rc.32那次旧备份；实际操作前另确认用户当前方便及无任务。当前播放状态未查询。

可先准备这样的脚本并离线验证绑定拒绝、坐标计算、状态截止/结果核查分支，再协调一次短同源观察。无需为此重建原生程序、准备rc.33、升采集FPS、改P4/RAF/latest或扩大trace容量。
