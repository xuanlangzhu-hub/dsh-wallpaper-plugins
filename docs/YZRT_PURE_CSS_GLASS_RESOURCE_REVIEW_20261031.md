## 对这个效果的判断

**适合作为材质参考，尚不适合直接当整套生产控件替换。**

1. 主要配方是六层内外阴影、2px backdrop blur、低透明白底、前后伪元素渐变亮边、文字／图标下方的影子。没有对背景做真正的几何位移或折射。这是可控的视觉模拟，名字中的“液态”不等于已实现动态光学折射。
2. 原始对象是100px圆形按钮和320×100px胶囊，字号33px。没有开关、滑块、选择器、状态反馈、键盘焦点、禁用／错误或深浅主题等完整控件实现。
3. 原版在浅色网格上玻璃体积感比较明显。只缩容器／文字到36px控件尺寸，原来的2/6/8/25px阴影和模糊仍是固定值，亮边和底部阴影比例变重。换深色线条背景后，固定黑字对比不足；两者都需要针对尺寸／背景适配，不能据此保证实机优于rc.60。
4. 全局 `*` 设置 `user-select:none` 与 `transition:.25s`，body重置布局，`.box`/`.fx-layer` 全局类和z-index500/501，不能整张样式表导入聊天宿主。视觉伪元素也需要从真实交互层分离。
5. `.fx-layer` 在整个容器上施加 `filter:contrast(3)`。这会影响子控件的背景采样边界，不能假设它能直接模糊宿主最底层壁纸。[CSSWG Filter Effects 2 草案](https://drafts.csswg.org/filter-effects-2/#BackdropRoot)描述了上层 filter 对 Backdrop Root 的影响，草案尚未形成完整共识；本轮未核定DSH对应Chromium下的具体边界。后续应测真实宿主祖先，而不是为了保留样图对比度直接套全局filter。

纯CSS可以减少额外JS／React依赖，但多层阴影、contrast和blur仍有渲染成本；本轮没有GPU或帧率测量，不能推断更省性能。

## 建议的下一小步

无需从零凭空设计玻璃配方，但仍需把材质层、原生按钮／开关／range语义和状态结合。保留播放与作者参数业务链，重做控件的最终呈现；重点核对默认appearance、宿主覆盖／伪元素、透明父层／背景采样、尺寸与缩放，不能继续仅添加装饰滤镜就称适配。

后续先在固定官方SDK的真实侧栏结构、真实字号／按钮尺寸中只处理一个播放按钮，用复杂明暗背景对照。先确认最终呈现，再扩开关／滑块；不先重画一套脱离宿主的漂亮样图。许可明确前只作为技术和视觉参考，不把上游代码直接放进现有MIT候选，也不把尚未定位的宿主叠层问题说成已解决。
