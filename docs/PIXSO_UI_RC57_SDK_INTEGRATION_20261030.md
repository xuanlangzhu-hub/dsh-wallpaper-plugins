## 错误与失败证据

没有把控制台当成“零警告”：各组仍严格核对既有bootstrap／disconnect的401身份和时序；gallery另有刻意制造的schema 409 `author_library_unavailable`和restart清理失败409。没有豁免其他错误，所有组pageErrors为空。

准备及补充检查中的失败保留：

1. `...-a`准备时，比较器把CRLF结束分隔符的CR误留在CSS正文，导致一字节不等。尚未创建runtime；改比较器后在新`...-b`准备，保留原文件及失败说明。
2. 首次生命周期脚本沿用了旧自引用文件名，读取源码证据时ENOENT，发生在开浏览器前。修正自引用，不改产品内容。
3. 透明度最初在未播放状态测量，之后虽已收到start回复仍没有实际帧；旧SDK夹具的stream本来只保连接、不送帧。client设计要求真实首帧后才露出壁纸并启用透明背景。给这一独立检查提供有限合成帧、确认实际绘制及背景标记后，透明度断言通过；未改产品门禁，也未伪设body状态。
4. 控件检查先做过正常播放，再接要求“无既往播放”的旧生命周期检查，历史start计数使其失败。保留原断言，将两类检查拆为全新页面的独立组后分别通过；不是扩大可接受计数。

失败轮浏览器和服务也都正常收尾、进程确认退出；前后运行产物始终同一指纹，未通过改产品源码迁就这些夹具错误。
