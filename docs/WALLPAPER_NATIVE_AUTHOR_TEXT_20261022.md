## 行为

每字段为作者标签、单行输入及原有忙碌/完成状态；短错误只在无效时出现，没有保存/应用按钮组。初始值仍为作者默认或插件记录，非WE当前值读回。

| 操作 | 结果 |
| --- | --- |
| 读取、聚焦或不改值完成 | 不发送默认值 |
| 普通输入 | 留在本地，不逐键下发 |
| 有效Enter或正常失焦 | 仅提交最终本字段，随后失焦不重复发送 |
| 空字符串、前后空格 | 按原样提交，不trim或强制转换 |
| 无效文本Enter | 不发送，保留输入供修正 |
| 无效文本失焦 | 丢弃本次输入并短提示未应用，不能发送先前有效片段 |
| Esc、窗口失焦、收起/切目标/卸载 | 取消尚未提交的编辑，不撤回已发送命令 |

复用原`validateAuthorValue`/`safeAuthorString`，沿用256个UTF-16单位和既有字符串限制，不新增多行、路径/HTML等协议能力。最终不使用HTML maxlength截断：超长文字或代理对字符保持可见但判无效，避免把截短的有效前缀当成用户完整内容提交。输入法使用临时本地文字，确认有效后才进入原draft/apply通道。

## 输入法事件边界

- composition期间不提交，不妨碍输入法消费自己的确认/取消按键。`isComposing`以及`keyCode=229`均阻止确认候选的Enter变成壁纸应用。
- compositionend只更新本地最终文字，不自动下发。若确认按键尚未结束，防线保留到相应keyup/新的明确编辑动作；不会把同一轮Enter当作第二个应用动作。
- 组合期间或确认按键仍受保护时失焦，保守取消，不发上一次有效前缀。
- 没有尚未结束的确认按键（例如鼠标选候选、前一输入按键已释放）时，结束组合仍不自动下发，但之后正常失焦可以提交。
- Esc发生于组合过程中先留给候选界面；组合结束后再次Esc才取消本字段。迟到compositionend不能重新创建被取消/失效的票据。

这是浏览器事件层的实现和检查，不是Windows真实输入法/候选窗矩阵验收；未更改系统输入法或操作日常应用。

## 协调与保护

新增纯本地`createNativeAuthorTextEditor`管理文本、错误、组合状态及确认按键边界，无计时器、轮询或独立IO通道。它订阅既有作者协调器，保留编辑中的本地文字；旧确认不覆盖新输入。编辑票据要求当前不可变字段描述符，绑定epoch/context/具体可见视图；旧字段、重读、代次ABA或另一编辑者不能接管。

提交前继续使用即时SDK `focusedTarget(inputNode)`核验，避免宿主先转移焦点、后通知隐藏时误把收起当正常失焦。主侧栏收起但仍可见的浮动文本页能正常提交，两个真实occurrence共享记录、控件ID不同。订阅/事件在关闭或卸载时释放。

只发送完成的本字段，快速完成多次保留最新值；原单执行通道、最多4批/总12秒、读取/清除4秒、物理请求未结束不解锁、revision/fingerprint、失败/未知及显式恢复规则保持。Host、协议和原执行器未改。
