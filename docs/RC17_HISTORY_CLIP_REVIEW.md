# R5 / rc.17：按输入卡片位置裁剪消息层

日期：2026-10-07。Codex 接手 DS 的未交付改动；**源码修复及隔离检查通过，真实 Desktop 观感尚未验收，未安装。** 日常 rc.1 保持原样。

## DS 改动与可复现原因

DS 已去掉座位/overlay 的大面积背景，保留输入卡片自身表面。但消息遮罩按 viewArea 整段内容的底部计算，不能代表 sticky 输入卡片所在的屏幕位置；透明到不透明的渐变也没有完全透明的平台，无法保证输入区旁的字消失。每次画帧还重建观察器，且只测一个座位、未跟踪会话更换。

使用记录的官方 CSS、官方消息与 composer 的兄弟结构、真实客户端和替身 Host，在 2200px 长消息层里重现：卡片外壁纸可见，DS 客户端仍有 72 行采样差异（最初复现）；之后补重复真实文本和两侧/底部连续采样，旧 DS 仍被拒绝。遮罩落在长内容的底部，显示区内仍能看到消息。不是 WE 解码或画面传输问题。

DS 删除的像素检查与原改动已保留到本轮专属证据，Git 历史中的旧检查也保留。`test:appearance-wallpaper-overlay` 恢复为像素检查的别名，不再转发一个无法证明遮挡效果的通过项。

## 修复

- 沿用 DS 的卡片表面与透明外围，不给座位/底部画黑底或宽黑渐变；顶部局部遮挡和按钮分组保留。
- 只对当前 active 会话滚动区内的消息兄弟 viewArea 应用 `clip-path`，不裁剪包含 composer 的滚动父层。
- 用消息层和真实输入卡片的 `getBoundingClientRect()` 计算裁剪边界，保证消息在卡片顶边处消失；参考的是消息自己的 border box，不是猜测的高度常数或渐变终点。
- 滚动/窗口尺寸/消息和输入尺寸/节点替换/会话阶段变化触发测量，合并到一个 animation frame。每个背景激活周期只创建一套观察器，不按 WE 每帧重建。
- 每个 view 单独记录临时属性和变量的旧值，停止、来源为无、卸载或节点退出时恢复；取消排队测量、断开观察器和事件，不留到日常主题。
- Host、原生 helper、长期帧循环、控制器公开接口、资源归属和自动播放语义未改。
