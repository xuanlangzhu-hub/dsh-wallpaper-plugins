## 结果

缺失/损坏值禁用且不假冒默认。无会话、只读控制器、未知或实际主题不一致、旧页占用、已卸载时拒绝写入。失败关联本字段短错误“暂时无法更改玻璃强度，请重试”，核对真实偏好，不编造回滚；写入后异常保留实际新值，同值明确重试不重复写入。

## 减少透明度的真实负例与修补

首次完整 SDK `glass-sdk` 在浏览器隔离模拟的 `prefers-reduced-transparency: reduce` 下失败：鲸雾的标准档正确为 `none`，切到克制档却回到 `blur(12px) saturate(112%)`。媒体查询已匹配，不能将其当作模拟未生效。失败源/QA保存在 `reduce-before/`，原浏览器脚本、报告及退出清理证明保留。

原因是原克制档选择器带 `data-wm-glass`，优先级高于较晚的减少透明度规则；深色配色规则中也有同类问题。本轮只在原减少透明度分支的**三处选择器列表**加入同等优先级的 `data-wm-glass` 变体：鲸雾、鲸渊和动态配色。旧选择器仍保留作后备，所有原CSS声明、普通模式外观参数与主题资产不改。

因此本轮不再声明client生成块外完全不变。`reduced-selectors.cjs` 和审计严格证明块外只有这三处列表增加；不是替换主题色或关闭全部玻璃效果。

修补后将减少透明度检查扩展到鲸雾及鲸渊四种配色、各两档，共10组合，均为 `none`；模拟结束后恢复浏览器媒体设置，偏好仍保存用户选择。只在自有headless浏览器内模拟，没有修改Windows设置。此修复尚未安装到日常rc.42。
