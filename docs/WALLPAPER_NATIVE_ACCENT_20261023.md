# 原生侧栏：强调色模式与自定义颜色

2026-10-23，接续[深色配色选择](WALLPAPER_NATIVE_PALETTE_20261023.md)。本轮只迁入既有强调色入口，并补齐该入口的失败重试；不制作候选、不操作日常应用。

## 结果

默认收起的“界面”分区，在主题和深色配色后新增“强调色”选择：**跟随主题 / 自定义**。两种 Whale 主题均可使用，自定义时才显示原生取色控件和只读 HEX 回声；选择颜色直接生效，不增加日常保存、应用按钮或成功说明段落。

原 `accentMode=theme/custom`、严格六位 HEX、原 controller 规范化与存储、body/CSS 投影和对比度派生均复用。新入口将合法 HEX 转为小写再写入。回到跟随主题时，原投影规则清除自定义变量，颜色偏好保留，再切回自定义恢复。主题资产、默认值、配色和四字段预设不改。

损坏或缺失模式显示未知，损坏颜色不显示伪造色块；这些状态禁用且不自动修复默认值。无会话、只读控制器、实际主题与偏好不一致、旧页占用及服务卸载时拒绝写入；颜色控件被隐藏后，滞留处理器也不能改色。模式和颜色错误分别关联自己的控件，只显示“暂时无法更改强调色，请重试”。拒绝/异常后读真实偏好，不编造回滚或成功。

## 同值取色重试的实际失败与修补

完整 SDK 第一轮在颜色已写入后注入异常：实际存储和 CSS 为 `#aabbcc`，控件诚实报错；再用取色控件选择同值，错误未清除，检查失败。诊断组 `retry-event-probe` 记录 DOM `input/change` 均发生，但 controller 调用数仍为91，错误仍为 true；单项直接同值调用则可完成核对。原控件的同值事件不能当成可靠的用户重试入口。

现在**仅颜色失败时**出现小型“重试”按钮：记住失败时用户希望应用的颜色，写入前失败时重新提交那个颜色；写入后失败时核对已经保存的同值，不重复写入。正常控件仍没有额外按钮。

重试记录绑定失败后的实际颜色、模式、偏好主题、实际主题和会话。任一状态发生变化即撤销记录，包括离开后又返回原值的 ABA；滞留按钮仍经过旧页互斥和卸载门禁，不覆盖后来修改。控件、短错误及重试按钮随原生服务释放。

旧失败源/QA快照在 `retry-before/`，原失败与事件探针报告保留；最终 SDK 保留“同值 fill 不清错误”的反例断言，再实际点击错误旁重试并核对恢复，没有把原失败改成成功预期。仅证据目录中保留诊断探针，产品无诊断计数或全局钩子。
