# 图库分页：独立滚动与透明底行

用户确定基础控件、透明底和细边框后，本轮只调整图库分页布局。源码及固定 rc.57 官方 Windows rc.3 SDK 检查完成；没有打包、安装或操作日常应用。

| Before | After | Why |
| --- | --- | --- |
| 分页 sticky 贴底、bottom 与 margin-bottom 为负值，整条实色背景 | 分页在卡片列表下方独占普通布局行，透明底，仅按钮保留细框 | 取消覆盖卡片的底栏，分页始终有自己的空间 |
| 搜索、筛选、卡片和分页共用页面滚动 | 普通高度下仅卡片区域滚动，搜索／筛选与分页留在各自位置 | 不必滚完整页才能翻页，也不会失去筛选入口 |
| 翻页沿用原滚动容器 | 按页码重新建立卡片容器，新页从顶部开始 | 避免换到第二页仍停在列表底部 |
| 矮窗口也容易形成拥挤的内层滚动区 | 窗口高度不超过400px时使用整页自然滚动 | 保留卡片实际高度与分页可达性 |

没有改每页12项、页码算法、年龄分级、搜索、选择／播放分离、播放切换、作者参数或诊断逻辑。单页和空结果仍不显示分页。

## 检查结果与失败记录

最终 `.tmp/gallery-pagination-sdk-20261031-d` 共15项SDK检查通过：原有11项基础控件／比例／作者滑块原链路检查，新增4项分页检查。

- 800／480px高度、280／420／570px栏宽下，分页始终位于卡片滚动区之后；滚至底部，末卡片底边不超出可视区，无横向溢出。
- 页码1→2→1真实点击，前后页禁用边界正确；翻页从顶部开始。在第2页选中卡片仍留在图库且不启动播放，最后恢复Lucy选择。
- 单项搜索／空结果隐藏分页；清空恢复，键盘Enter可翻页。
- 330px矮窗口改用自然流，分页可真实点击；深浅主题均为透明分页行。

实际420px栏宽、800px高度：12卡片分6行，每行138.5px，滚动区420px、内容879px，底部scrollTop459。截图为合成数据／占位缩略图，不是日常壁纸加载结果。

源语法、生成同步、CSS模板guard通过。原始失败不覆盖：

1. SDK-a准备脚本用Windows默认GBK读UTF-8源码失败，浏览器尚未启动；后改为明确UTF-8。
2. SDK-b发现卡片行被浏览器压到约62px，未实际产生滚动；SDK-c追加测量确认。这是真实布局缺陷，随后添加`grid-auto-rows: max-content`，保留卡片内容高度。
3. SDK-d同样的滚动断言通过，未降低要求或扩大期限；父运行器约5.17秒、退出0且已确认，无超时。

最终页面JS错误为0，原精确`/api/main/snapshot`及`/api/main/disconnect`的401基线仍在，不能称控制台零错误。自有浏览器确认退出，HTTP／bridge关闭；订阅、引用、监听和对象URL归零，42个URL创建与撤销一致，无带消费者撤销。没有原生／WE IO。
